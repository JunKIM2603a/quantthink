## 생성 중 마스크·cache와 처리량

80응답에서 마스크/cache 표본432행을 읽었다. 모두 `DynamicCache`, `implicit_sdpa` 경로이고 저장된 과거/현재 키 차단 수는0이다. 과거가 있는 표본은28계층 cache 길이가 현재 위치와 일치한다.4094/4095/4096은 각각44응답,8191/8192는 각각35응답,16383/16384는 각각26응답,32767은18응답에서 관측됐으며 도달해야 할 경계의 누락은 없다. 입력은59~110토큰, 실제 입력+출력 최대는32,878토큰이다.

이는 실제 생성 중 **Qwen2 마스크 함수 반환과 cache 길이의 저장 표본**에 대한 검토다. `None` 마스크는 고정 SDPA 구현의 implicit 경로이며 GPU kernel 내부의 독립 관찰·모든 토큰의 수치 검증은 아니다. 이번 기록에서는 과거4096 sliding window 차단이 남았다는 증거가 없지만, 이것만으로 AWQ 종료/반복 문제의 원인을 판정하지 않는다.

완료40응답의 생성 호출 시간 합은 BF16 4,808.76초, AWQ 25,167.05초이며 처리량은 각각33.32·32.60토큰/초다. 로딩·recipe 복원·파일 저장·중단된 호출 시간은 제외한다. AWQ는 양자화된 값을 BF16 연산으로 재적용한 경로이고 `native_low_bit_kernel=false`이므로 native 3비트 가속 성능 평가가 아니다.

이전4K 시험과 비교하면 상한과 유효 window 설정이 함께 바뀌었다. 공통으로 기록된 runtime flag는 같고 이번에는 `cudnn_allow_tf32=false`가 추가 기록됐지만 이전 보고서에는 이 항목이 없다. 과거 대비 변화를 순수한 상한의 인과 효과로 추정하지 않는다. 위 상한별 표는 이번 동일 경로 내부 비교다.

## 해석과 다음 작업

이번 자료에서는 긴 상한에서도 BF16/AWQ의 종료·유효 최종 답·제한 길이에 큰 차이가 관찰된다. AWQ의 숫자/문장 반복과 EOS 종료 시 유효 답 부재도 확인됐다. 이는 더 긴 관측이 필요했던 이유와 그 한계를 함께 보여준다. 자체20문제의 탐색 결과이며 양자화 구현 오류인지 정상적인3비트 손실인지, 어떤 분포/후보집합 변화가 원인인지까지 가르지는 못한다.

다음은 **좌표 변환의 기능적 수락 점검과 독립 확인 기준 결정**이다. 준비된 [새16문맥 점검](FUNCTIONAL_HOLDOUT_V01_KO.md)은 B/S·Q/C·C/Cw의 변환 영향을 별도로 살피는 최대96회 forward·새 생성0의 범위이며 아직 실행 승인 전이다. 이 결과를 그96회의 승인으로 바꾸지 않는다.32K가 AWQ에 충분했다고 선언하거나64K/새시드/새문제로 자동 확장하지 않는다.

미래 확인에서는 EOS 도달, 유효 최종 답, 최종 정답, 상한 내 길이를 따로 기록해야 한다. 이미 본20문제와 사후 반복 사례는 탐색 자료로 보존하고 독립 표본으로 재사용하지 않는다. 기존 자동 평가기를 현재 답변에 맞게 소급 수정하지 않으며 수동 보완 규칙을 향후 평가에 채택하려면 적용 시점을 별도로 고정한다.

세션02의 남은 종료 조건은 좌표 변환의 기능적 수락, 평가기의 일반 타당도, 독립 확인의 재현 기준이다. 생성/cache 표본과 처리량 근거는 이번에 확보했지만 기능적 동등성·종료 지연의 인과 원인은 미확정이다. 세션03으로 전환하지 않는다.
