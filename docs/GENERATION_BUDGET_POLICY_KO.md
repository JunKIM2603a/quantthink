# 이후 추론 생성 시험의 토큰 예산 원칙

2026-09-30 사용자가 토큰 상한 확대 재시험과 이후 충분한 상한 적용을 요청했다. 이 정책은 그 요청을 반영한 운영 원칙이며 R1·MATH-500·KL 매칭·H1/H2·7B의 실행 승인이 아니다.

1. **새 자유생성 추론 시험의 기본 상한은32768토큰으로 계획한다.** EOS가 먼저 나오면 즉시 끝낸다. [DeepSeek 공식 평가](https://github.com/deepseek-ai/DeepSeek-R1#4-evaluation-results)의 최대 생성 길이를 참고한 출발점이며 모든 모델/문제에 충분하다는 보장은 아니다. 다른 상한을 고르면 목적·근거·총 계산 예산을 사전 기록한다.128/4096을 계속 기본값으로 복사하지 않는다.
2. **출력 상한과 전체 문맥을 따로 확인한다.** prompt+생성이 모델 지원 길이를 넘지 않게 하고 원치 않는 sliding window·입력 절단·cache 축소가 없는지 기록한다. 설정을 고쳤으면 이전 결과와 상한만 달라졌다고 쓰지 않는다.
3. **비교 조건에는 같은 상한을 적용한다.** 한쪽 모델만 늘리거나 유리한 종료 사례만 고르지 않는다. 같은 긴 생성 경로에서4K·8K·16K·32K 예산별 종료율·검열률·min(길이,상한)을 읽어 예산 의존성을 남긴다.
4. **충분성은 종료 자료로 확인한다.** 개발 점검에서 모델별 검열률5% 이하를 운영 목표로 삼되 표본 수·분모를 밝힌다. 정답률/자연 길이 동등성 보장이 아니다. 검열이 남으면 관측/미관측 부분을 구분하고 전체 자연 길이 평균을 채워 넣지 않는다. 전체 표본의 자연 길이 관측이 목적이면 검열0이 필요하다.
5. **무제한 증액하지 않는다.** 총 응답 수·상한·총 생성 예산을 사전 기록하고 오류·중단·재개에서 소비 계산을 보존한다.64K 이상이나 새 문제/시드/모델 확대는 후속 범위로 정한다. 공식 확인 자료의 결과에 맞춰 상한을 사후 조정하지 않는다.
6. **기존 기록과 비생성 진단은 그대로 둔다.** 동결된 R0/4096 설정·결과를 수정하지 않고 새 버전·결과 폴더를 만든다. 고정 prefix의 logit 계산은 새 생성0이므로 출력 상한 확대 대상이 아니다. 짧은 연결 점검이 필요하면 자유생성 본시험과 목적·한도를 구분한다.
