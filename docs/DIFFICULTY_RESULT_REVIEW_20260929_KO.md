## 난도별 관측

각 셀의 분모8은 **4문제 × 2시드**다. 자동 정답은 EOS 종료와 최종 답 파싱·정답 일치를 모두 만족한 수이며, 검열은 응답 상한 종료다.

| 난도 | BF16 자동 정답 | AWQ 자동 정답 | BF16 EOS | AWQ EOS | BF16 검열 | AWQ 검열 |
|---|---:|---:|---:|---:|---:|---:|

종료 후 형식 미판정은 BF16 3개, AWQ 1개다. 자동 정답·형식 미판정·검열을 더하면 조건별40개이며, INCORRECT와 ERROR 기록은 없다. 전체 자동 성공률55% 대27.5%는 **현재 예산·종료·파싱 조건을 함께 적용한 성공률**이다. 검열된 응답의 최종 정오를 알 수 없으므로 이를 완전 관측 정확도로 쓰지 않는다.

두 시드 모두 자동 성공한 문제 수는 D1~D5 순서로 BF16 **3·2·3·1·0/4**, AWQ **2·1·1·0·0/4**다. BF16의 자동 성공이 D2보다 D3에서 높기도 하다. D1~D5는 자체 임시 난도이며 공식 MATH Level이나 실측 난도 순서가 아니다.

사전 PASS는 8개 모두 EOS·채점 가능하고 안정 통과가3/4 이상일 때다. D1 BF16도 두 형식 미판정 때문에 이를 충족하지 않는다. **두 조건의 모든 난도는 INCONCLUSIVE이고 확정된 통과 경계는 없다.** 이것은 실행 실패나 차이 부재의 뜻이 아니다. 결과를 보고 사전 기준을 낮추지 않는다.

## 지금 실행할 읽기 전용 명령

새 `scripts/export_difficulty_review.py`는 기존 run.json을 채점 계약으로 읽어 기존 summary.json과 대조하고, 전체 생성문·ID·실행 기록을 비공개 검토 파일로 복사한다. 같은 폴더의 재개 백업이 있으면 바이트 해시와 보존된 응답 앞부분을 대조한다. 원본 파일·고정 계획·모델·예산은 변경하지 않는다.

아래 옵션은 **기존 캐시의 고정 config.json만** 읽는다. 모델·토크나이저 로딩, GPU 연산, calibration, 네트워크 다운로드는 없다. SDPA 경고와 관련된 설정을 실제 입력+생성 길이와 함께 검토하기 위한 것이며, 경고가 결과 차이의 원인이거나 무해하다는 사전 결론은 아니다. 캐시를 찾지 못하면 그 상태를 기록하고 기존 결과 묶음은 작성한다.

```bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates &&
git pull --ff-only &&
python scripts/export_difficulty_review.py \
  --run results/local/difficulty_v01/run.json \
  --summary results/local/difficulty_v01/summary.json \
  --include-cached-model-config \
  --output results/local/difficulty_v01/review_evidence_v01.json
```

생성된 `review_evidence_v01.json`을 대화에 첨부한다. 전체 생성문·ID가 들어 있으므로 공개 저장소에 커밋하지 않는다. 이미 같은 출력이 있으면 덮어쓰지 않고 그 파일을 사용한다. 원본/요약 불일치가 나오면 원본을 보존하고 오류를 검토한다. 현재80개가 제출됐으므로 실행·재개 명령을 다시 수행할 필요는 없다.

새 내보내기 코드의 CPU 검사5개가 통과했다. 원본·전체 ID/텍스트 보존, 오래된 요약/종료 필드 불일치 거부, 백업/응답 앞부분 대조, 기존 출력 보호, 모의 캐시의 오프라인 호출과 해시 불일치를 검사했다. 실제 사용자 run.json·Hub 캐시는 아직 받지 않았고 모델/GPU·기존 R0/준비 검사는 실행하지 않았다.

1. 기존 기록의 실행 commit·환경·디코딩·파라미터 해시·재개 보존을 확인하고,80개 생성 ID로 종료를 재검산한다. 캐시 설정과 실제 문맥 길이도 대조한다.

3. 그 근거를 [기존 좌표·logit 후속 계획](R0_DIAGNOSTIC_FOLLOWUP_20260929_KO.md)에 연결한다. 동일 입력 prefix에서 B/S/Q/C/Cw를 비교할 위치와 허용 기준을 실행 전에 정한다. 서로 다르게 생성된 문맥의 logit을 그대로 비교하지 않는다. 기존 기록에는 전체 logit이 없으므로 텍스트 검토만으로 이 진단이 완료되지는 않는다.

좌표/norm·전체 모델 logit 검증과 평가 타당도가 남아 있어 **세션02를 유지한다**. 검열 문제만으로4096→8192 확대를 자동 실행하지 않는다. 자체 난도 시험은 MATH-500 재현이 아니며, MATH train 확대 후보·새 Pile 입력·R1·KL 매칭·장문맥·H1/H2·7B도 실행하지 않는다. 이번 결과는 다음 점검의 초점을 정하는 탐색 근거다.
