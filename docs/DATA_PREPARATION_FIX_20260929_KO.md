# 데이터 준비 중단 수정 — Pile JSONL 행 길이

작성일: 2026-09-29  
검토 기준 commit: `a640e64acc967878571ad2d955ce5fc2f7f65d73`  
수정 당시 세션: **QuantThink 01 — 저장소 점검·연구 설계 검증**

**준비 코드의 JSONL 행 길이 한도가 실제 고정 Pile 파일의 한 행보다 작아 중단됐다. 해당 파일을 독립적으로 내려받아 해시와 전체 행을 확인하고 읽기 한도를 수정했다.** 이후 사용자 재실행 성공을 [데이터 준비 완료 검토](DATA_PREPARATION_REVIEW_20260929_KO.md)에 기록했다. 이 문서는 오류 수정 당시의 근거와 명령을 보존하며, 지금 데이터 준비를 반복할 필요는 없다.

## 1. 실제 원인

사용자 로그에는 pyarrow 20.0.0·zstandard 0.23.0 설치 확인, 원본 다운로드 계획 340,798,261 bytes, 토큰 길이 경고, 행 제한 오류가 있었다. 이전 코드는 행 수 초과와 행 길이 초과에 같은 오류 문구를 사용했다.

작성 환경에서 고정 revision의 Pile validation 원본을 내려받고, 공식 Hub 메타데이터의 LFS SHA-256과 파일 바이트를 대조했다. 기존 코드로 동일 오류를 재현했다.

| 확인 항목 | 실제 값 |
|---|---:|
| 압축 파일 크기 | 338,045,152 bytes |
| 전체 JSONL 행 수 | 179,996 |
| 오류 행의 0부터 시작하는 인덱스 | 76,409 |
| 사람이 세는 행 번호 | 76,410번째 |
| 해당 행 길이·전체 최대 행 길이 | 4,744,757자, 줄바꿈 포함 |
| 기존 한 행 읽기 한도 | 4,194,304자 |
| 해당 행의 text.strip() 길이 | 1,106,669자 |
| calibration 문서 문자 길이 한도 | 65,536자 |

따라서 행 수 상한 1,000,000개가 원인이 아니다. 큰 JSON 행을 읽기 전에 중단돼, 원래 정책의 문서 문자 길이 제외 절차까지 도달하지 못했다. 이 문서는 전체 JSON을 읽은 뒤 기존 길이 기준으로 제외할 수 있다. JSON 행의 문자 수와 디코딩된 text 값의 문자 수는 escape·메타데이터 등의 영향으로 다를 수 있다.

확인한 원본:

- 저장소: `monology/pile-uncopyrighted`
- revision: `3be90335b66f24456a5d6659d9c8d208c0357119`
- 파일: `val.jsonl.zst`
- SHA-256: `db5e5d1532bf8dc33a6589b50ecba1a8c96f7b4b9cb343d168e603c393007c26`
- [고정 파일 페이지](https://huggingface.co/datasets/monology/pile-uncopyrighted/blob/3be90335b66f24456a5d6659d9c8d208c0357119/val.jsonl.zst)

사용자 컴퓨터의 원본 파일 바이트를 직접 읽은 것은 아니다. 위 수치와 해시는 작성 환경에서 같은 고정 원본을 확인한 결과이며, 사용자 실패 로그와 구분한다.

## 2. 수정 내용

- Pile calibration에 사용하는 읽기 한도만 **8,388,608자**로 명시했다. 일반 JSONL 읽기의 기본 4,194,304자 한도와 전체 행 수 상한은 유지했다. 이 값은 모델 문맥 길이가 아니라 JSON 파서의 자원 한도다.
- 큰 행을 통째로 읽어 유효한 JSON인지 확인한다. 행을 잘라 해석하거나 건너뛰지 않으므로 뒤쪽 원본 행 번호도 보존한다. 8,388,608자를 넘는 행은 자동으로 한도를 늘리지 않고 오류로 처리한다.
- 행 수·행 길이·JSON 구문 오류를 구분하고 파일명, source_row, 실제 행 번호와 해당 상한을 표시한다.
- calibration manifest에 읽은 전체 행 수, 최대 행 길이, 기존 기본 한도 초과 행 수와 적용한 한도를 기록한다. 빈 문서·문자 길이·토큰 길이에 따른 제외 개수도 별도로 남긴다.
- 토큰화에 `add_special_tokens=False, truncation=False, verbose=False`를 명시한다. 문서를 자르지 않고 전체 토큰 수를 센 뒤 **512토큰 초과 문서를 기존대로 제외**한다. 모델에 입력하지 않는 후보 검사에서 발생하던 길이 경고는 이 호출에서만 표시하지 않는다.
- 파일 바이트 확인·개발 후보 선택·calibration 검사 시작·완료를 콘솔에 표시한다.

사용자 로그의 `17692 > 16384` 경고는 Transformers가 토큰화 결과 길이를 보고 출력한 안내다. 그 문서를 모델에 입력했다는 의미가 아니며, 이번 준비 코드에는 모델 가중치 로딩·생성이 없다. 512토큰 기준을 완화하거나 tokenizer의 문맥 한도를 변경하지 않았다. [Transformers v4.51.3 공식 구현](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/tokenization_utils_base.py)의 encode/encode_plus와 길이 경고 조건을 확인했다. 해당 파일 blob은 `8e047569e7ce56573949b4e03aa9f1057802bf90`이다.

## 3. 확인한 범위

| 검사 | 결과 |
|---|---|
| 고정 원본 파일 바이트 | 파일 크기·LFS SHA-256 일치 |
| 수정 전 읽기 코드 | 76,409행을 읽은 뒤 다음 행에서 사용자와 같은 오류 재현 |
| 수정 후 실제 압축 JSONL 전체 읽기 | zstandard 0.23.0에서 179,996행 JSON 해석 통과 |
| 새 회귀 검사 | 11개 통과. 큰 문서와 큰 메타데이터 구분, 원본 행 번호, 한도·Unicode·EOF·구문 오류, 문서 제외·미절단, 전체 준비 연결 검사 |
| 기존 v0.3 연계 검사 | 32개 중 29개 통과, PyTorch·Transformers 의존 검사 3개 건너뜀 |
| zstandard 버전 추가 대조 | 0.23.0에서 압축 프레임·전체 준비 연결 검사 2개 재확인. 앞선 11개와 별개 검사로 합산하지 않음 |
| 구문 검사 | 변경 스크립트와 새 테스트 통과 |

단위 검사 환경은 Python 3.12.14, NumPy 2.3.5, zstandard 0.25.0이다. 사용자 버전에 맞춘 별도 zstandard 0.23.0으로 실제 전체 파일 읽기와 압축 관련 두 검사를 확인했다. 작성 환경에서 실제 토크나이저를 실행하거나 개발·calibration 후보 전체를 생성한 것은 아니다. 준비 연결 회귀 검사는 Hub·Parquet·토크나이저를 모의 객체로 대체했다.

기존 후보·점검 참조·v0.3 정책 JSON 3개의 해시는 그대로다. 표본 선택 seed·순서·적격 기준·블록 크기·문제 중복 제외를 변경하지 않았다. runtime_assets.py의 데이터 읽기 부분은 바뀌므로 코드 해시는 갱신된다. 이전 합성 AWQ PASS는 당시 대조 commit의 근거로 유지하며, 새 코드 전체를 GPU에서 재실행한 것으로 기록하지 않는다. AWQ 함수 연결 구현은 변경하지 않았다.

## 4. 오류 수정 당시의 재실행 명령 기록

아래는 오류 수정 직후 전달한 명령이다. 당시 오류는 출력 디렉터리 생성 전에 발생했으므로 같은 경로를 사용할 수 있었다. 이후 해당 경로에 성공 산출물이 만들어졌으며 지금 다시 실행할 명령이 아니다.

~~~bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates
git pull --ff-only

python -m unittest discover -s tests -p 'test_data_preparation_limits.py' -v

python scripts/prepare_runtime_assets.py \
  --mode all --online \
  --output-dir results/local/runtime_assets_v03
~~~

새 회귀 검사 11개 통과를 확인하고 데이터 준비로 진행한다. 완료 상태는 `PREPARED_CANDIDATE_NOT_RUN_APPROVAL`이다. 다른 실행에서 결과 폴더를 이미 만들었다면 새 경로를 지정하고 조회 경로도 맞춘다. 기존 결과를 삭제하거나 덮어쓰지 않는다.

성공 후 [합성 AWQ 검토 문서 5절의 요약 명령](SYNTHETIC_AWQ_REVIEW_20260929_KO.md)을 실행해 출력을 공유한다. 이번 요약에는 `jsonl_reader`도 포함된다. 동일한 고정 원본이라면 행 수 179,996, 최대 행 길이 4,744,757, 기존 기본 한도 초과 행 수 1이 예상된다. 개발 100문제·calibration 65,536토큰과 실제 선택 해시는 준비 완료 보고서에서 따로 확인한다.

## 5. 연구 상태

이 수정 당시 데이터 준비는 **사용자 실행 중단 → 원인 재현·코드 수정 → 사용자 재실행 대기** 상태였다. 이후 개발 100문제·calibration 65,536토큰의 성공 보고를 검토했다. 최신 근거와 다음 단계는 [완료 검토](DATA_PREPARATION_REVIEW_20260929_KO.md)와 [R0 검토안](R0_REVIEW_PACKET_20260929_KO.md)을 따른다. 이후 사용자 승인으로 세션 02로 전환했다. 현재 R0 실행 안내는 [인계문](HANDOFF_01_TO_02_KO.md)에 있다.
