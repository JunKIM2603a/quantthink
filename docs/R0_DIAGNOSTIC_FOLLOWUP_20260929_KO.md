## 1. 코드에서 확인한 측정 의미와 남은 증거

| 저장 항목 | 실제 비교 | 기존 파일로 가능한 확인 | 기존 파일만으로 불가능한 확인 |
|---|---|---|---|
| scale_only_output_difference | 같은 계층 입력에서 원래 BF16과 양자화 전 스케일 적용 계층의 출력 | rms·relative_rms·max_abs 및 최댓값 계층 | 최대 오차의 토큰·채널 위치, 출력 분포, 전체 모델 영향 |
| canonicalized_output_difference | AWQ 변환 상태와 역변환 배열을 BF16 파라미터로 다시 적용한 계층의 출력 | 같은 집계값 | 전체 모델 logit 동등성, 차이의 원인이 반올림뿐인지 여부 |

**오차의 수치 공간이 다르다.** awq_weight_space.py는 역변환 배열을 float64로 계산한다. canonical_weight_error와 canonical_auxiliary_error는 그 배열을 기준으로 한다. qwen2_awq_adapter.py의 출력 비교는 그 배열을 BF16 파라미터로 다시 복사한 뒤 측정한다. 현재 저장된 가중치 오차를 향후 BF16 가우시안 대조군에 그대로 적용하고 실제 가중치 변화량까지 일치했다고 말할 수 없다.

canonical_weight_error에는 양자화·clipping과 스케일 연산의 수치 효과가 함께 들어간다. 이 값이 0이어야 한다는 통과 기준은 부적절하다. auxiliary RMS가 0보다 크더라도 크기의 의미와 출력 영향을 확인하지 않고 구현 실패로 분류하지 않는다. 반대로 작은 절대 RMS만으로 무시해도 된다고 결론내리지 않는다.

run_r0.py에는 전체 모델 logit, AWQ 체크포인트, 전체 모델의 변환 전/후 파라미터 해시, 생성 RNG 상태 저장이 없다. 계층 JSON의 scales·clips 기록은 존재하지만 이것이 검증된 모델 체크포인트라는 뜻은 아니다. 필요한 자료가 없다는 이유로 R0 전체나 AWQ 탐색을 자동 반복하지 않는다.

## 2. 제출 완료된 읽기 전용 확인

[summarize_r0_diagnostics.py](../scripts/summarize_r0_diagnostics.py)는 Python 표준 라이브러리만 사용한다. 모델/토크나이저·CUDA·외부 네트워크·데이터 준비 코드를 호출하지 않으며 결과 파일을 쓰거나 바꾸지 않는다.

확인 항목:

1. run.json과 계층 파일의 현재 바이트 SHA-256, 0~27번 계층의 누락·중복·파일명/내부 번호 일치.
2. 계층별 7개 weight 범위, norm/bias 목록 일관성, 기록된 오차의 유한성. 파라미터별 원소 수 가중 RMS·최대 상대 RMS와 해당 계층을 요약한다.
3. 생성 4건의 조건·fixture·seed, BF16/AWQ 입력 ID 일치, 생성 ID에서 길이·EOS·검열 재집계와 저장된 종료 필드 대조. 마지막 허용 토큰이 EOS이면 예산 도달과 자연 종료를 동시에 기록하고 검열로 세지 않는다.

원소 수가 다른 텐서의 RMS는 단순 평균하지 않는다. 전체 원소 RMS는 `sqrt(sum(n_j * rms_j^2) / sum(n_j))`다. 상대 RMS가 null인 항목은 0으로 바꾸지 않고 별도로 남긴다. 보조 파라미터는 참조 RMS가 없어 상대오차를 만들어내지 않는다.

이 도구는 저장된 오차 집계를 요약한다. 원시 가중치나 활성값으로 진단을 다시 계산하거나 scales·clips의 실제 연산을 검증하지 않는다. 생성 텍스트·전체 토큰 ID·scales/clips 배열도 출력하지 않는다. think 종료 토큰 위치는 구조 정보이며 최종 답변의 정오 라벨이 아니다.

아래는 이미 제출된 요약을 생성한 명령의 기록이며 재실행 요청이 아니다.

~~~bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates
git pull --ff-only
python scripts/summarize_r0_diagnostics.py --result-dir results/local/r0_v03
~~~

종료 코드 0은 요청한 집계에서 구조 불일치를 찾지 못했다는 뜻이고 동등성 PASS가 아니다. 1은 출력의 structural_issues를 검토해야 한다는 뜻이다. 2는 파일 누락·파싱 오류 등으로 요약하지 못했다는 뜻이다. 어느 경우도 모델·데이터 준비 재실행을 자동으로 요구하지 않는다.

출력 JSON을 첨부로 전달받아 검토했다. 같은 요약을 다시 요청하지 않는다. 원본 29개 파일의 해시는 이후 같은 파일 집합인지 확인할 표식이다. 해시를 보고받는 것만으로 수신자가 사용자 원본 파일 바이트를 직접 검증한 것은 아니다. results/local의 원본과 요약은 공개 Git에 올리지 않는다.

## 4. 후속 logit·좌표 점검의 구체적인 초안

이 절은 **새 모델 점검 계획**이다. 아직 실행하지 않으며 기존 R0 승인에 포함됐다고 보지 않는다. 기존 파일 요약 제출·검토는 완료됐고, 다음은 이 계획의 실행기를 준비하는 작업이다. 기존 R0의 재승인을 요청하지 않는다.

공통 입력은 기존 BF16 생성 2건의 입력 ID와 128개 생성 ID를 연결한 두 고정 시퀀스다. 보고된 입력 길이 기준 전체 길이는 150·161토큰이다. 생성된 128개 토큰을 예측한 위치 및 상한 직후 다음 토큰을 예측하는 위치를 포함해 문제당 129개 logit 위치를 비교한다. 동일한 위치 집합을 모든 상태에 사용한다. 새 생성·새 문제·KL 매칭·AWQ 탐색은 이 진단 설계에 필요하지 않다.

| 상태·비교 | 목적 |
|---|---|
| B: 동일 고정 BF16 참조, 같은 입력으로 2회 | 현재 runtime의 동일 모델 반복 오차 확인 |
| S: 저장된 scale만 적용한 모델; B↔S | 양자화 전 재매개화의 전체 모델 영향 |
| Q: 저장된 scale/clip을 재적용하고 고정 quantizer로 변환한 모델; B↔Q | 양자화의 관측 효과 크기. 같아야 한다는 동등성 검사는 아님 |
| C: Q를 원래 좌표로 복원하고 BF16으로 재적용; Q↔C | 실제 실행될 좌표 복원의 전체 모델 영향 |
| Cw: C의 선형 weight만 유지하고 norm/bias를 원래 BF16으로 복원; C↔Cw | weight 외 파라미터 잔차를 제외할 때의 영향. 자동으로 주 AWQ 조건을 바꾸지 않음 |

제안 계산량은 두 입력 × 다섯 상태의 full-sequence forward와 B 반복 두 번, 총 12회다. cuda:0·기존 BF16/SDPA·고정 버전·use_cache=false·동일 attention mask/position을 사용하고 상태는 순차 로딩한다. 원시 가중치 준비와 좌표 재구성 비용은 forward 12회와 별도이며 실제 소요 시간은 아직 측정하지 않았다. 이 계획은 생성의 KV cache 경로와 장문맥을 검증하지 않는다.

Q 재구성은 저장된 scale/clip dtype·shape·순서·clipping·pseudo quantization을 고정 원본 함수와 대조한 구현이 먼저 필요하다. R0 당시 전체 AWQ 파라미터 해시가 없으므로 재구성 결과가 당시 AWQ와 비트 단위로 같다고 인증할 수 없다. 기존 진단과의 일치는 보조 근거다. 이 한계를 기록하고 재구성 상태의 새로운 해시를 보존한다. 재구성이 불가능하면 그 원인을 보고하며 탐색을 자동 반복하지 않는다.

추가 저장 항목:

- float64 역변환 배열과 BF16 재적용 파라미터의 오차를 각각 기록. norm/bias의 참조 RMS·절대 RMS·상대 RMS·max_abs와 위치를 저장. 참조가 0이면 상대값은 null.
- 공통 prefix의 logit RMS·max_abs와 위치, top-1 일치/변경 및 참조 top-1/2 margin. 분포 진단은 온도 1, top-p 적용 전 전체 vocabulary에서 FP32 log_softmax로 계산한 KL·TV와 EOS log-probability 차이를 기록. 이는 교란 매칭 실험이 아니다.
- B↔S, Q↔C, C↔Cw와 B↔Q를 분리해 보고. 생성 경로가 다른 두 응답의 logit을 같은 위치라는 이유만으로 직접 비교하지 않음.

판정은 두 단계다. 먼저 12회 실행·입력/위치 일치·유한 값·변환 범위·비교 쌍 기록이 충족되면 **진단 자료 수집 완료**로 분류한다. 누락·비유한 값·변환 계약 불일치는 엔지니어링 실패 또는 미완료다. 다음으로 기능적 수락 여부를 판단한다. **기능적 허용오차의 수치 경계는 미정이며 이 초안은 자동 PASS를 내지 않는다.** BF16 반복 오차는 수치 바닥을 파악하는 근거이고 그 자체가 스케일 변환의 허용 한도는 아니다. 후속 독립 점검 전에 수치 정밀도·출력 분포 및 EOS 민감도에 대한 근거로 한도를 문서화해야 한다. 임의의 소급 기준을 적용하는 대신, 그 전의 측정은 탐색 진단으로 남긴다.

## 5. 종료 관측을 위한 별도 후속 초안

logit·좌표 점검 결과와 모델 상태 재구성 문제를 검토한 뒤에만 결정한다. 실행 후보는 **기존 합성 2문제 × BF16/AWQ × seed 42, 최대 512토큰씩 총 4회·새 생성 최대 2,048토큰**이다. 다른 decoding·prompt·모델·calibration 조건은 유지한다. 이는 기존 128토큰 승인의 **예산 확대 제안**이며 미승인·미실행이다. 512는 길이 효과를 검정하는 예산이 아니라 한 번의 한정된 종료 관측 후보 상한이다.

R0는 RNG 상태를 저장하지 않았다. 따라서 저장된 128토큰 뒤에서 seed만 다시 설정한 생성을 원래 샘플링의 연속 실행으로 취급하지 않는다. 후속 생성은 같은 시작 조건에서 별도 실행하고, 첫 128토큰의 일치 여부도 기록한다. cap 변경만으로 앞부분의 비트 단위 일치가 보장된다고 가정하지 않는다.

| 후속 관측 | 판정 |
|---|---|
| 네 응답 모두 실제 EOS로 종료, 종료 ID/카운트 일치 | 해당 네 건의 자연 종료 관측 완료. 마지막 512번째 토큰이 EOS여도 자연 종료로 셈 |
| 일부 또는 전부 EOS 없이 512토큰 도달 | 해당 건은 right_censored=true, 예산 안 자연 종료 미관측. 자동으로 1,024/장문맥으로 늘리지 않음 |
| EOS 후 토큰 존재, budget 초과, 원인 없는 조기 종료, 오류 | 기록/생성 경로 엔지니어링 조사 |

종료 확인과 정답 평가는 분리한다. 완성된 최종 답변 영역의 42·12를 사람이 확인해 파서 결과와 대조할 수 있지만, 두 합성 문제만으로 GSM8K/MATH-500 평가기·정답 포기 라벨의 타당성을 인증하지 않는다. 이 네 건으로 자연 길이의 분포 차이나 AWQ 길이 증가를 확증하지 않는다.

## 6. 세션 종료 조건과 이번 변경의 검증 범위

세션02 종료 조건인 기능적 양자화 검증·사전 재현 기준 판정·평가 타당도는 미완료다. R1·MATH-500·교란/KL 매칭·장문맥·H1/H2·7B 실행 범위를 확대하지 않았다. 이 초안 작성 당시 다음 행동은 고정 입력 참조를 이용한 전체 모델 진단 실행기 준비였다. 이후 난도 시험 원본에서 문맥 경계 문제가 구체화돼, 현재는 맨 위 최신 검토의 CPU 마스크 함수 확인이 우선이다. 새 GPU forward의 범위는 기존 R0 승인과 구분한다.

요약 도구의 새 CPU 검사는 원소 수 가중 RMS, 상대 RMS 미정 처리, EOS가 마지막 허용 토큰일 때의 검열 처리, 파일 불변, 누락/중복·종료 기록 불일치, 잘못된 수치와 없는 입력 경로를 다룬다. 전부 합성 JSON에 한정하며 기존 R0·데이터 준비·토크나이저·합성 AWQ 테스트를 반복한 것이 아니다. 이 검사는 이전 턴의 기록이다. 이후 사용자 상세 집계값은 [상세 검토](R0_DETAIL_REVIEW_20260929_KO.md)에 추가했으며 새 모델 결과는 없다.
