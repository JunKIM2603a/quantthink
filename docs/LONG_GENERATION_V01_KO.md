# 32K 상한·전체 문맥 재시험 v01 — 부분 진행·SSH 복구 준비

최신 상태: 사용자 터미널에서 완료57개·시작58회·D3-01/AWQ/seed43 미완료를 보고받았다. [SSH 복구 안내](LONG_GENERATION_SSH_RECOVERY_20260930_KO.md)에 따라 원본과57개를 보존하고 남은23개를 재개한다. 원래 아래80회 예산과 별도로 중단1회 재시작만 허용하여 합산최대81회·2,654,208토큰이다. 이32K 원본/생성ID는 아직 미수신이며 결과 해석은 보류한다.

현재 세션은 **QuantThink 02 — 환경 구축·BF16/AWQ 재현**이다. 사용자의 2026-09-30 08:27:53 한국시간 요청 “토큰 수 제한을 늘려서 다시 시험하고, 앞으로의 시험도 토큰 수 제한을 충분히 늘리는게 어때?”를 제한된 재시험의 수행 근거로 기록한다. 아래 숫자는 요청을 구현한 기본값이며 사용자가 각 숫자를 따로 명시했다는 기록은 아니다. 같은 상한 확대 요청의 승인을 다시 묻지 않는다. 원래 R0 승인과 기존 결과는 변경하지 않는다.

## 상한 확대의 목적과 한계

기존20문제·80응답 중43개가4096토큰에서 잘렸다(BF16 15/40, AWQ 28/40). 따라서 최종 정답과 자연 종료 길이 비교에 큰 제약이 있다.128토큰 R0는 연결 확인용이었고4096도 실제 추론 길이를 충분히 관측하기에는 부족했다. 더 긴 답변을 먼저 관측하는 방향으로 우선순위를 바꾼다. 새16문맥·96회 좌표 점검은 미승인 상태로 보류하며 이번 재시험에 섞지 않는다.

상한 확대는 검열을 줄이지만 좌표 변환의 비영 차이·평가기 형식 처리·실제 생성 마스크·종료 지연 원인을 모두 해결하지는 않는다. 길어진 응답도 끝나지 않으면 right_censored=true다. 반복 중 정답 숫자가 나온 것을 최종 정답이나 정답 포기로 판정하지 않는다.

상한32768은 [DeepSeek 공식 평가 설명](https://github.com/deepseek-ai/DeepSeek-R1#4-evaluation-results)의 최대 생성 길이를 참고했다. 공식 평가의 자료·표본 수를 재현한다는 뜻이 아니고, 우리 AWQ가 이 안에 모두 끝난다는 보장도 아니다.

실행 시간은 미측정이다.32768은 모든 응답이 반드시 쓰는 길이가 아닌 최대값이다. 상한을8배로 늘렸다고 시간이 정확히8배가 되는 것은 아니며 긴 문맥의 처리 비용과 실제 종료 길이에 따라 달라진다.

## SDPA 문맥 경계 처리

기존 CPU 점검에서는 use_sliding_window=false여도 sliding_window=4096 때문에 이전 키가 차단되는 분기를 관측했다. 출력 상한만 늘리고 이 설정을 유지하면 오래 생성해도 앞 문맥이 가려질 수 있다. 새 시험은 전체 문맥 설정을 양쪽 모델에 동일하게 적용한다.

**과거와 이번 시험의 차이를 상한만의 효과로 해석하지 않는다.** 상한과 유효 문맥 설정이 함께 바뀐다. 대신 이번 동일 생성 경로에서 여러 상한의 결과를 추출한다. 생성 중 첫 prefill·첫 decode와 도달한4096/8192/16384 부근 등에서 실제 Qwen2 마스크 함수 반환과 DynamicCache 계층 길이를 기록하고 과거 키 차단·cache 길이 누락이 보이면 중단한다. None 마스크는 고정 SDPA 코드의 implicit 경로다. CUDA kernel 내부 직접 추적이나 수치적 동등성 인증은 아니다.

## 한 번 생성하고 네 가지 예산으로 읽기

각 응답을 EOS 또는32768까지 한 번 생성한다. 같은 경로에서4096·8192·16384·32768까지의 결과를 집계하며 네 번 따로 생성하지 않는다.

- **예산 내 종료율:** 각 상한 이내 EOS로 끝난 비율. EOS가 정확히 상한 위치에 있으면 자연 종료다.
- **검열률:** 해당 상한까지 EOS가 관측되지 않은 비율. 오답률로 바꾸지 않는다.
- **상한 내 관측 길이:** min(종료 길이, 상한)의 평균. 계획 응답이 모두 모였는지와 분모도 기록하며 전체 자연 길이 평균으로 부르지 않는다.
- **최종 정확도:** EOS 후 최종 영역을 기존 규칙으로 채점한다. 새 형식 미판정은 수동 검토 목록에 남긴다. 과거 수동 보완 정답을 새 생성에 자동 복사하지 않는다.
- **난도 판정:** 기존 자체 문제의 단계 규칙을 유지한다. 불완전·검열·형식 모호함은 INCONCLUSIVE이며 공식 MATH 난도나 독립 확증으로 해석하지 않는다.

각 모델의 검열률5% 이하를 예산 충분성의 운영 목표로 둔다.40응답 중2개까지라는 작은 표본의 기준이며 통계적 보증이 아니다. 검열이 하나라도 남으면 모든 자연 길이를 관측했다고 쓰지 않는다.32768에서도 검열이 많으면 현 설정에서 종료 실패가 지속된다고 보고하고,64K 이상 증액이나 별도 반복 진단은 결과 검토 뒤 결정한다. 자동 증액하지 않는다.

## 실행·중단·재개

한 번에80응답을 실행한다.15초마다 진행 토큰 수를 표시하고 응답 하나가 끝날 때마다 원본과 요약을 저장한다.

```bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates &&
git pull --ff-only &&
python scripts/run_long_generation.py --execute
```

시간을 나눠 실행하려면 **위 전체 실행 대신** 아래처럼 한 호출에서8응답을 완료한 뒤 멈출 수 있다.8은 총 문제/예산 변경이 아닌 호출당 작업량이다.

```bash
conda activate quantthink
cd ~/quantthink
python scripts/run_long_generation.py --execute --max-attempts 8
```

응답 사이에서 정상적으로 멈춘 완료분은 아래 명령으로 보존·백업한 뒤 이어간다.80개가 모두 있으면 모델 로드 없이 끝난다.

```bash
conda activate quantthink
cd ~/quantthink
python scripts/run_long_generation.py --execute --resume --max-attempts 8
```

생성 도중 Ctrl+C·OOM·오류가 나면 시작한 호출과 오류를 기록하고 자동 재생성하지 않는다. 그 경우 run.json과 로그부터 검토한다. 미완료 응답의 KV cache/RNG 전체를 복원하는 재개 기능은 아니다. 기존 결과를 삭제하거나 출력 폴더를 바꿔 예산을 초기화하지 않는다.

완료 후 새 폴더의 run.json과 summary.json을 제출한다. 전체 생성문/ID는 공개 Git에 올리지 않는다.

## 준비 검증과 상태

새 CPU 검사9개에서 상한 경계 EOS, 예산별 검열과 길이, 검열의 오답/성공 오분류 방지, 불완전 자료, 완료분 재개·소비 횟수, cache/마스크 오류와 범위/해시 차단을 확인했다. 기존 시험은 반복하지 않았다. 작성 환경에는 PyTorch/Transformers/GPU가 없어 실제32K 모델 실행과 cache trace는 아직 검증하지 못했다.

최초 준비 시점에는 사용자 GPU 실행 전이었다. 이후57개 완료·58번째 미완료 보고에 대한 제한 복구를 구현했고 새 CPU 검사11개가 통과했다. 현재는 **사용자 재개 실행·완료 결과 검토 대기**다. 세션02·model_ready=false·H1/H2 미검증을 유지한다.
