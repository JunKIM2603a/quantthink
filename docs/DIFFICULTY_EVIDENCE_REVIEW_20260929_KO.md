## 형식 미판정4개는 단위 표현

4개 모두 정확히1개의 think 닫힘과 최종 박스, 마지막 EOS를 갖는다. 최종 영역 전체를 읽었으며 박스 뒤에는 단위/대상 설명만 있고 답 번복은 없다.

|---|---:|---|---|
| D1-04 BF16 42 |126|제곱센티미터|정답|
| D1-04 BF16 43 |126|제곱센티미터|정답|

v01 파서는 박스 뒤 일반 문자를 모두 거부하므로 단위 설명도 `TEXT_AFTER_FINAL_BOX`로 남겼다. 기존 자동 평가기·점수·결과 파일을 바꾸지 않고 **사후 수동 보완표**를 추가한다. 각 수동 판정은 응답 레코드와 최종 영역의 해시에 묶었다. 중간 풀이에 나온 숫자는 정답 근거로 사용하지 않았다.

**수동 보완표에서는 BF16 D1이8/8 EOS·정답,4/4 안정 통과로 난도 조건을 충족한다.** AWQ는 D1부터 검열이1개 있어 경계를 확정하지 못한다. 나머지 단계도 검열 때문에 보류다. 원래 v01 자동 난도 판정10개는 모두 INCONCLUSIVE로 보존한다. 이 구분은 기준을 낮추는 것이 아니라 이미 계획된 수동 검토의 결과를 별도로 보고하는 것이다. MATH 공식 난도·벤치마크 재현이나 기능적 양자화 인증은 아니다.

수동 보완 후 양쪽 EOS인12쌍은 모두 양쪽 정답이다. BF16만 EOS인13쌍도 모두 BF16 정답이며 AWQ의 최종 정오는 미관측이다. “AWQ 오답이13개 증가했다”는 해석은 하지 않는다.

## 검열43개에서 확인한 내용

- BF16 11개와 AWQ 28개는 실제 ID/텍스트에 닫는 think 태그가 **0개**다. 여러 번 나온 경우는 없다. 이전 요약의 missing-or-multiple 모호함을 해소했다.
- 나머지 BF16 4개는 think를 닫았지만 최종 답 작성 중 잘렸다. D3-01 seed42, D4-02 seed42, D5-01 seed43, D5-02 seed43이며 최종 영역에는 박스가0개다. 생각 영역의 박스를 최종 답으로 옮기지 않는다.
- 검열 응답의 말미에는 재계산·자기수정·반복이 보인다. AWQ D4-03 seed43과 D5-03 seed42에서는 짧은 문장의 반복도 확인했다. 이는 일부 관측 구간의 기술이며 전체 추론의 논리 검증이나 정답 포기 라벨 검증이 아니다.

두 AWQ 사례는 문맥4096 이전에도 동일한16토큰 조각이 각각49회·64회 나타난다. 생성 앞부분을 각각4027·3991토큰까지만 사용한 겹침 허용 계수다. 사후 기술 통계이며 반복률의 사전 PASS 기준이나 H1/H2 검정으로 쓰지 않는다.

## SDPA 경고와 문맥 경계

이번에 받은 고정 config.json에는 `use_sliding_window=false`, `sliding_window=4096`이 함께 들어 있다. 설정의 정규화 해시는 기존 고정 참조와 일치한다. 실제 입력은59~110토큰이며, 입력+저장 생성은 최대4206토큰이다. 따라서 **출력 상한4096과 전체 문맥4096은 다르다.**

고정 [Qwen2 설정 코드](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen2/configuration_qwen2.py)는 두 값을 그대로 유지한다. [모델 코드](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen2/modeling_qwen2.py)의 경고 조건과 공통 causal-mask 작성 부분은 `use_sliding_window`를 확인하지 않고 `sliding_window` 값을 사용한다. [마스크 유틸리티](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/modeling_attn_mask_utils.py)도 key/value 길이4096부터 명시적 마스크 경로를 사용한다. [SDPA 연결 코드](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/integrations/sdpa_attention.py)는 그 마스크를 attention 함수에 전달한다.

소스에 따른 **DynamicCache 경로의 예상 동작**은 다음과 같다. 위치는0부터 세며 마지막 입력 토큰도 query 위치에 포함된다. 이 표는 소스 검토 시점의 예상이다. 이후 설치 소스 해시와 CPU 결과를 받아 아래 [후속 검토](SDPA_MASK_REVIEW_20260929_KO.md)에서 동일한 동작을 확인했다.

| query 위치 | key/value 길이 | 기록 설정의 예상 마스크 | 차단되는 이전 키 |
|---:|---:|---|---:|
|4094|4095|SDPA 기본 인과 처리|0개|
|4095|4096|명시적 마스크|0개|
|4096|4097|명시적 마스크|0번1개|
|4204|4205|명시적 마스크|0~108번109개|

이 경로에서는 sliding-window 사용 플래그가 false여도 경계 이후 오래된 토큰이 제외될 수 있다. 따라서 경고가 중단 원인이 아니었다는 이전 판단은 유지하지만, **이번 긴 응답에서 의미 없는 경고라고 취급할 수는 없다.** 생성에 사용된 cache 객체·마스크를 당시 직접 저장하지 않았으므로 실제 생성 영향은 후속 검증 대상이다. 모델의 max_position_embeddings=131072만으로 이 경로가 검증되는 것도 아니다.

전체 문맥4096을 넘은 기록은44개(BF16 16, AWQ 28)다. 검열43개 전부와 BF16 D4-04 seed43의 EOS 응답1개가 포함된다. 조건별 영향 기회가 다르므로 같은 backend를 사용했다는 이유만으로 비교에서 상쇄됐다고 가정하지 않는다.

한편, 새 생성 없이 **공통 생성 prefix3986토큰**만 재검토했다.3986=4096−최대입력110이며 마지막 예측의 key/value 길이는 최대4095다. 고정 소스의 문맥 경계 진입 전 구간에서도 BF16 EOS24/40, AWQ12/40이다. 양쪽EOS12쌍, BF16만EOS12쌍, 반대0쌍, 양쪽미종료16쌍이다. 따라서 경계 이전에도 종료 차이가 남는다. 이는 사후 민감도 확인이며 기존4096 예산·점수·응답을 덮어쓰지 않는다. 전체 자연 길이나 AWQ만의 인과 효과를 확증하지 않는다.
