# 실제 난도·길이를 반영한 후속 시험안

현재 세션: **QuantThink 02 — 환경 구축·BF16/AWQ 재현**

상태: **사용자의 입력 난도 확대 의견을 반영한 설계 제안. 구체적 표본·예산 미수락, 데이터 선택·새 모델 실행 미실행.**

## 1. 이번 의견의 반영과 기존 결과의 의미

사용자는 두 산수 문제가 너무 간단해 차이를 보기 어렵다고 지적하고 MATH-500 또는 Pile-uncopyrighted validation 수준의 입력을 제안했다. 추론 행동을 평가할 문제 난도·생성 길이를 확대하는 방향은 타당하다. 기존 산수 두 문제에 대한 12회 전체 모델 forward만으로 연구 대상의 대표성을 확보할 수 없으므로, 그 계획은 짧은 입력 연결 점검 후보로만 남긴다. 그것과 512토큰 산수 재생성부터 반복하는 것을 후속 작업의 기본 경로로 삼지 않는다.

다만 '쉬운 문제라 불일치가 없었다'는 원인 해석은 현재 근거와 구분해야 한다.

- structural_issues=[]는 계층/파일·기록의 내부 일관성이다. BF16과 AWQ의 행동이나 분포가 같았다는 결과가 아니다.
- 두 산수 생성의 닫는 think 태그 앞 토큰은 BF16 57·78, AWQ 101·99였다. 차이가 전혀 없었던 것도 아니며 두 사례로 일반적인 길이 증가를 확인한 것도 아니다.
- **기존 28계층 출력 진단은 산수 두 문제로 계산하지 않았다.** run_r0.py가 고정 calibration 블록을 run_awq에 전달하고, qwen2_awq_adapter.py는 그 128 × 512 = 65,536개 Pile 토큰의 참조 활성값으로 계층 출력을 비교한다. 약 0.6% 상대 RMS를 단순히 산수 문제의 쉬움 때문이라고 설명할 수 없다.
- Pile 진단은 AWQ 탐색에 사용한 동일 calibration 입력이다. 선택 밖 문서에서의 일반화, 전체 모델 logit 누적 영향, 실제 수학 생성 경로, 긴 문맥·KV cache 검증은 여전히 별개다.

검토 기준 HEAD는 `32b40b456a17d845e9b04cba6a19cdf74f5901f1`이다. 모델을 새로 실행한 관측은 없다.

## 2. 데이터 역할

| 자료 | 용도 | 이번 결정/제안 |
|---|---|---|
| 기존 합성 산수 2개 | 로딩·생성·종료 기록의 최소 점검 | 완료된 R0 근거로 보존. 연구 대표성의 근거로 확대하지 않음 |
| 이미 사용한 Pile 128×512 | AWQ calibration 및 그 입력 위의 계층 진단 | 그대로 보존. 재준비·재탐색하지 않음 |
| calibration과 문서가 겹치지 않는 Pile validation 부분 | 일반 텍스트에서 좌표 변환·norm 복원·logit 비교 | 보조 수치 진단 후보. 'validation'이라는 원본 split 이름만으로 독립성을 주장하지 않음 |
| 원래 MATH의 train 분할 | MATH 계열 난도를 갖춘 개발·예비 생성 시험 | 우선 추천. 여기서 train은 원본 데이터 분할 이름이며 이번 모델 학습을 뜻하지 않음 |
| MATH-500 | 고정된 최종 확인용 수학 평가 | 현재 확증용 역할 유지. 예비시험의 예산·허용치 조정에 사용하지 않음 |

MATH-500은 문제·풀이·정답·과목·난도 등이 있는 MATH 부분집합이다. Pile-uncopyrighted는 여러 출처의 일반 텍스트 코퍼스이며 모든 행이 수학 문제/정답 쌍인 자료가 아니다. 따라서 두 자료를 동일한 '문제 난도' 기준으로 볼 수 없다. Pile에는 수학적 텍스트가 있을 수 있지만 표준화된 최종 수학 답안 평가·정답 포기 라벨을 제공하지 않는다.

## 3. 제한된 수학 예비시험 후보

아래 수치는 실행 요청 이전에 검토할 **초안**이다. 기존 R0 승인이나 원래 GSM8K 100문제 R1 후보를 소급 변경하지 않는다. 원래 H1/H2·허용 경계·MATH-500 확인 계획도 동결하지 않는다.

| 항목 | 제안 |
|---|---|
| 자료 후보 | 원래 MATH train. 검토한 접근 후보는 EleutherAI/hendrycks_math이며 파일 출처·revision·바이트·원본 분할 대응은 준비 때 고정 |
| 표본 | 7과목 × Level 2~5 × 각 1문제 = 28문제. 기초 비교점부터 어려운 문제까지 포함하는 탐색 표본이며 통계적 확증용 표본 수가 아님 |
| 선택 | 답이나 모델 출력을 보기 전 과목·난도별 고정 seed/해시 추출. MATH-500 문제와 정규화 중복 대조. 부족한 층·메타데이터 미정·중복 제외를 보고하고 임의 대체하지 않음 |
| 모델·조건 | 기존 고정 1.5B BF16과 기존 scale/clip을 재사용해 재구성한 AWQ-W3. 재구성 가능성·수치 검증은 선행 구현 과제 |
| 샘플링 | 조건별 seed 42·43, 동일 prompt·T=0.6·top_p=0.95·top_k=0·repetition_penalty=1 |
| 생성 상한 후보 | 응답당 최대 8,192토큰. 28 × 2조건 × 2seed = 112회, 새 생성 합계 최대 917,504토큰. 실행 시간·처리량 실측치는 아직 없음 |
| 기록 | 입력 길이, 태그 전 구간 길이, 전체 생성 길이, EOS/상한 종료, 검열, 최종 답·파서 상태, 실제 생성문 수동 검토, 시간·메모리 |

8,192는 제안한 예비시험 상한이며 논문 원본과 동일한 예산이나 자연 종료 보장이 아니다. 현재 R0는 128토큰 생성만 확인했으므로 위 예산의 메모리·문맥·cache 경로도 미검증이다. 입력 토큰 상한·전체 문맥 상한과 오류/메모리 중단 규칙을 실행 계획에서 확정해야 한다. 어려운 문제만 넣어 BF16부터 대부분 실패하게 만드는 구성, 출력에서 차이가 큰 문제만 골라 보고하는 구성은 피한다.

기존 GSM8K 수치 평가기를 MATH에 그대로 사용하지 않는다. 분수·수식·집합 등 정답 형식의 동치 판정과 파싱 실패를 처리하는 평가기가 필요하다. 답안 평가는 최종 답변 영역을 대상으로 하고, 추론 중 정답 숫자 출현을 정답 포기로 자동 분류하지 않는다.

## 4. 길이와 기능 진단의 확장

입력 문장의 길이, 문제 난도, 모델이 생성한 추론 구간 길이는 다른 축이다. 긴 지문만 골라 추론 난도가 높아졌다고 보거나, 인간용 Level 라벨을 해당 1.5B 모델의 실제 난도와 같다고 가정하지 않는다. 입력 길이를 기록하고 난도별 결과와 구분한다.

전체 모델 진단은 B/S/Q/C/Cw 비교 구조를 유지하되, 다음 입력 종류를 구분해 확장한다.

1. calibration 밖 Pile 문서: 자연 텍스트 입력에서 스케일·좌표 복원의 수치 영향을 확인한다. 문서 ID/내용 해시를 기존 calibration manifest와 대조한다.
2. MATH 개발 문제의 공통 BF16 생성 prefix: 실제 수학 풀이 초반과 뒤쪽 위치에서 logit·분포·EOS 확률 및 norm 복원 영향을 비교한다. 생성 전에 비교 위치 규칙을 정하고, 해당 길이에 도달하지 않은 경우는 미관측으로 남긴다.

두 종류의 지표를 섞어 한 평균으로 통과시키지 않는다. 제공된 정답 풀이를 teacher forcing 입력으로 쓰는 경우도 BF16이 직접 생성한 경로와 구분해 라벨링해야 한다. 기존의 전체 모델 진단 실행기 준비 작업을 버리지 않되 산수 2개만을 유일한 입력 계약으로 고정하지 않는다. 확장할 Pile 문서 수·토큰 길이·추론 prefix 위치 수는 실행기와 자료 준비에 맞춰 후속으로 확정한다.

## 5. 사전에 구분할 해석

- 충분한 EOS 관측과 평가 타당도가 있는 상태에서 길이·정확도·종료가 달라지면 해당 예비 표본에서의 탐색적 차이로 기록한다. H1의 가우시안 대조군 비교는 아직 수행하지 않은 상태다.
- 양쪽이 비슷하더라도 이 작은 예비시험만으로 동등성을 인증하지 않는다. 난도·시드·검열·불확실성을 함께 보고한다.
- 상한 종료가 많으면 자연 종료 길이의 비교는 계속 미완료다. 제한 길이·상한 도달률을 보고하며, EOS로 끝난 사례만 골라 전체 길이 평균을 비교하지 않는다. 예산을 차이가 보일 때까지 자동으로 올리지 않는다.
- 원래 BF16에서도 대부분 오답이면 정답 포기를 판단할 기회 자체가 적을 수 있다. 기존 표본 결과를 보존하고 후속 표본 설계를 별도로 기록한다.

## 6. 다음 준비 작업과 승인 범위

후속 준비의 우선순위를 실제 난도 표본·출력 예산·평가기 및 다양한 입력을 지원하는 전체 모델 진단 실행기로 바꾼다. 28문제/8,192토큰 후보의 데이터 ID·revision·평가기·총 문맥 한도는 아직 확정되지 않았으므로 실행 가능한 확정 프로토콜이라고 부르지 않는다.

사용자의 의견은 난도 확대 방향의 근거로 기록한다. MATH-500 전체 실행·위 신규 예산·Pile 새 추론·R1·H1/H2·7B 실행을 포괄 승인한 것으로 바꾸지 않는다. 세션 02와 model_ready=false를 유지한다.

## 확인한 자료

- [MATH 원 논문](https://arxiv.org/abs/2103.03874): 문제 풀이용 competition mathematics 데이터라는 성격을 확인. 이번에는 초록을 읽었으며 새 전체 논문 검토로 기록하지 않음.
- [MATH 원 저장소](https://github.com/hendrycks/math): 저자·데이터/평가 코드 연결 확인.
- [MATH-500 데이터 페이지](https://huggingface.co/datasets/HuggingFaceH4/MATH-500): test 500행, problem/solution/answer/subject/level/unique_id 필드 확인. 모델 생성·튜닝에는 사용하지 않음.
- [MATH train 접근 후보](https://huggingface.co/datasets/EleutherAI/hendrycks_math): 과목별 부분집합·train 분할·problem/level/type/solution 필드 확인. 전체 파일·revision·원본 바이트 대응 검증은 아직 아님.
- [Pile-uncopyrighted 데이터 카드](https://huggingface.co/datasets/monology/pile-uncopyrighted): 일반 언어 모델용 코퍼스와 text/meta 형식 확인. 현재 calibration revision·자료 해시는 기존 검토 참조를 유지.
