# 32K 재시험의 SSH 단절 복구 — 완료 57개 보존

현재 세션은 **QuantThink 02 — 환경 구축·BF16/AWQ 재현**이다. 사용자가 SSH 단절 후 재시작 방법을 요청하고, 이어서 완료 57개·시작 58회·미완료 `D3-01 / awq_w3_replay / seed 43`인 터미널 출력을 제출했다. 이 요청을 해당 중단 한 건의 복구 근거로 기록한다. 같은 재시작 요청의 승인을 다시 묻지 않는다.

## 확인한 근거와 한계

- 터미널 출력의 상태는 `LONG_GENERATION_RUNNING`, error는 null이다. `pgrep` 출력에는 해당 Python 프로세스가 나타나지 않았다. JSON의 RUNNING은 마지막 저장 상태이며 지금도 프로세스가 실행 중이라는 증거는 아니다.
- 최초 `--execute`는 기존 결과 폴더 보호 때문에 중단됐다. 일반 `--resume` 검사도 미완료 호출의 계산 소비를 감추지 않기 위해 차단됐다. 완료 결과가 삭제됐다는 메시지가 아니다.
- 저장소 기준은 `2aef0938bdf8292ddc0423cd350a235ebe4c199a`이다. 복구기는 사용자 원본의 실행 commit·기존 코드 13개·설정·입력/종료 계약·모델 파라미터 해시·정확한 중단 위치를 실행 전에 대조한다. 이 환경에서는 사용자 GPU의 32K 원본 `run.json`이나 57개 생성문/ID를 받지 않았으므로 실제 원본 대조가 끝났다고 기록하지 않는다.
- SSH 단절은 사용자 보고다. 실제 프로세스 종료 원인을 포렌식으로 확정한 것은 아니다. 미완료 호출의 실제 생성 토큰 수·KV cache·RNG 전체는 저장되지 않았다.

## 복구 동작과 계산 기록

1. GPU와 모델을 불러오기 전에 기존 결과 폴더의 실행 잠금을 확인한다. 다른 실행이 잠금을 유지하면 복구하지 않는다. 원본을 읽어 일치 여부만 검사한다.
2. 실행 준비 후 같은 잠금을 다시 잡고 원본을 다시 검사한다. 현재 설치 패키지·입력 ID·생성/문맥 설정·기존 참조·수치 코드 호환성을 확인한 뒤 원본 바이트를 `run.before_resume.<SHA-256>.json`으로 백업한다. 기존 백업은 덮어쓰지 않는다.
3. 저장된 57개 행과 원래 실행 메타데이터는 보존한다. 미완료 호출은 `recovery_ledger.abandoned_attempts`에 옮겨 별도 기록한다. `generation_calls_started`는 **58에서 유지**하며 57로 줄이지 않는다.
4. `D3-01 / awq_w3_replay / seed 43`을 처음부터 다시 생성하고 이후 순서대로 진행한다. 총 남은 완료 대상은 이 응답을 포함해 **23개**다. BF16 40개와 AWQ 17개 완료분을 다시 생성하지 않는다. AWQ 저장 recipe 재적용은 메모리의 모델을 복원하는 과정이며 새 calibration 탐색이 아니다.
5. 완료 응답 80개를 모두 모으면 물리적 생성 호출은 중단분을 포함해 81회다. 반복 플래그가 추가 허용량을 계속 늘리지 않으며, 두 번째 도중 중단/오류는 다시 차단한다. 완료된 80개에 같은 명령을 입력하면 모델을 불러오지 않고 종료한다.

| 항목 | 고정한 한도/기록 |
|---|---|
| 원래 시험 | 자체 20문제 × 2모델 × 2시드 = 완료 대상 80개 |
| 원래 동결 예산 | 최대 80회 × 32768 = 2,621,440 생성 토큰 |
| 이번 재시작에 따른 추가 허용 | 중단 한 건을 위한 생성 최대 1회·32768토큰 |
| 합산 상한 | 최대 81회·2,654,208 생성 토큰 |
| 미완료 호출의 실제 토큰 수 | 알 수 없음(null). 소비 상한은 32768로 별도 보존 |
| 재개 후 생성 대상 | 23개, 최대 753,664토큰 |
| 변경하지 않은 조건 | 문제·시드·상한·모델·AWQ recipe·decoding·window=None·use_cache=true |

원래 `configs/long_generation_v01.json`을 소급 수정하지 않고 `configs/long_generation_ssh_recovery_v01.json`에 한 건의 추가 허용과 코드 이전을 따로 기록한다. 기존 코드 13개에서 복구 코드 14개로의 정확한 해시 조합만 허용하고 공통 코드 11개는 동일해야 한다. 재개 실행 구간에 새 commit·코드·연구 상태 해시를 저장한다. 원본 보고서의 최초 commit/코드 해시는 보존한다.

미완료 응답을 토큰 중간부터 이어 쓰는 기능은 아니다. 동일한 시드를 다시 설정하지만 저장되지 않은 미완료 경로와의 비트 단위 일치를 주장하지 않는다. 정답·길이·종료 결과에 따라 다시 뽑는 재시험도 아니다.

## 실행 명령

현재 사용자 결과 폴더에서 아래 명령을 한 번 실행한다. 브랜치 갱신에 실패하면 생성은 시작하지 않는다. `nohup`과 표준 입출력 분리로 SSH 연결이 끊겨도 실행을 유지하도록 한다. 서버 재부팅·OOM 등까지 막는 기능은 아니다.

```bash
conda activate quantthink
cd ~/quantthink
if git switch setup/session-01-research-gates && git pull --ff-only; then
  nohup python -u scripts/run_long_generation.py \
    --execute --resume --recover-interrupted \
    >> results/local/long_generation_v01/resume.log 2>&1 < /dev/null &
  printf '재개 프로세스 PID: %s\n' "$!"
fi
```

진행 로그는 별도로 본다.

```bash
conda activate quantthink
cd ~/quantthink
tail -n 30 -F results/local/long_generation_v01/resume.log
```

로그 조회 중 `Ctrl+C`는 조회만 끝낸다. 백그라운드 생성은 계속된다. 최초 복구에서는 `저장 57개 보존 / 남은 23개`와, 모델/recipe 복원 후 `시작 58/80 awq_w3_replay D3-01 seed=43`이 예상된다. 물리적 호출 번호는 이때 59이며 중단된 58회째를 숨기지 않는다. 완료 후 상태는 `LONG_GENERATION_EXECUTED_PENDING_REVIEW`다.

복구기가 원본 불일치·다른 실행·새 오류를 보고하면 JSON의 상태나 횟수를 수동으로 고치거나 결과 폴더를 지우지 않는다. 해당 로그를 다음 검토 근거로 남긴다. 완료 후 같은 폴더의 `run.json`과 `summary.json`을 비공개 첨부로 제출한다. 생성문/ID 전체를 공개 Git에 올리지 않는다.

## 구현 검증과 남은 작업

새 CPU 검사 11개에서 57개 보존, 원본 바이트 백업, 미완료 호출 회계, 23개 완료 후 80행/81회 한도, 반복 플래그의 멱등성, 추가 중단 차단, 코드/설정 불일치 거부, 잠금 상태의 중복 실행 차단을 확인했다. 합성 JSON 검사이며 기존 R0·자료 준비·tokenizer·합성 AWQ·모델 시험을 재실행하지 않았다. 이전 코드와 모델 로드·생성 설정·AWQ replay·파라미터 해시·시드·generate·종료 기록·마스크 추적의 AST 8개도 일치한다.

작성 환경에는 PyTorch/Transformers/GPU가 없어 실제 GPU 복구를 실행하지 않았다. 현재는 **사용자 부분 진행 보고 수신·제한 복구 코드 준비 완료·사용자 재개 실행 대기**다. 완료 57이라는 수만으로 EOS·정답·난도 통과·자연 길이를 판단하지 않는다. 세션 02 종료 조건은 여전히 미충족이며 `model_ready=false`다. 새16문맥96회·R1·MATH-500·KL 매칭·H1/H2·7B 범위는 확대하지 않는다.
