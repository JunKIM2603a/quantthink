## 3. weight 오차와 보조 파라미터 잔차

아래 상대 RMS는 **파라미터 종류별 28계층 중 최댓값**이다. 계층 평균이나 모델 정확도 감소율이 아니다. 원래 BF16 weight에 대한 좌표 복원 AWQ weight의 차이이며 float64 역변환 배열 기준이다.

| weight 종류 | 최대 상대 RMS | 해당 계층 |
|---|---:|---:|
| mlp.down_proj | 28.2093% | 2 |
| mlp.gate_proj | 25.0669% | 3 |
| mlp.up_proj | 21.2134% | 19 |
| self_attn.k_proj | 33.2473% | 5 |
| self_attn.o_proj | 20.6178% | 27 |
| self_attn.q_proj | 33.9499% | 0 |
| self_attn.v_proj | 36.0887% | 25 |

모든 weight 종류에서 28계층 모두 비영 오차이고 미정 상대 RMS는 없다. 이 값에는 양자화·clipping·스케일 연산의 수치 효과가 함께 들어간다. 위의 약 0.6% 계층 출력 진단과 비교 대상·단위가 다르므로 두 수치를 모순으로 보거나 어느 하나를 정확도 손실로 해석하지 않는다.

| 보조 파라미터 | 28계층 원소 수 가중 RMS | 최대 계층 RMS | 해당 계층 | 비영 계층 |
|---|---:|---:|---:|---:|
| input_layernorm.weight | 0.0010933686 | 0.0016979741 | 27 | 28/28 |
| post_attention_layernorm.weight | 0.0012260220 | 0.0021970595 | 27 | 28/28 |
| q_proj.bias | 0 | 0 | 전 계층 | 0/28 |
| k_proj.bias | 0 | 0 | 전 계층 | 0/28 |
| v_proj.bias | 0 | 0 | 전 계층 | 0/28 |

이 표의 RMS는 **절대값**이다. 참조 norm 크기가 저장되지 않아 0.1% 같은 상대오차로 바꿀 수 없다. 또한 BF16 재적용 전 배열의 값이므로 실제 모델 파라미터 잔차의 크기와 전체 모델 영향도 추가 측정 대상이다.

관측에 따라 후속 초점을 **두 LayerNorm**으로 좁힌다. 선형 weight만 교란하는 가우시안 대조군을 나중에 만들 경우, AWQ 좌표 복원 과정에 남는 norm 변화를 어떻게 다룰지 확인해야 한다. 아직 norm 잔차가 행동 차이를 만들었다거나 무시할 만큼 작다고 판단할 근거는 없다. bias는 이번 보고에서 잔차가 없으므로 별도 bias 교란 조건을 추가하지 않는다.

## 4. 전체 응답 검열과 think 종료 위치의 구분

모든 생성에서 닫는 think 토큰 151649가 한 번 보고됐다. 위치는 생성 ID의 0-based index이므로 그 값은 닫는 태그를 제외한 앞쪽 생성 토큰 수와 같다. 입력에 이미 들어 있던 여는 think 태그는 이 수에 포함하지 않는다.

| 합성 문제 | BF16: 닫는 태그 앞 토큰 | AWQ: 닫는 태그 앞 토큰 | AWQ−BF16 | 태그 뒤 기록된 토큰 BF16/AWQ |
|---|---:|---:|---:|---:|
| 17 + 25 | 57 | 101 | +44 | 70 / 26 |
| 3줄 × 4개 | 78 | 99 | +21 | 49 / 28 |

태그 뒤 토큰 수는 `128 − 앞쪽 토큰 수 − 닫는 태그 1개`로 계산했다. 이 값은 상한에 남은 출력 공간이며 완성된 최종 답변 길이가 아니다.

**이 두 응답에서는 태그 앞 구간이 AWQ에서 더 길었다는 기술적 관찰이 가능하다.** 닫는 태그가 실제로 관측됐으므로 이 구간은 전체 응답처럼 128토큰 끝까지 미관측인 상태는 아니다. 단, 이는 두 합성 문제·한 sampling seed에서 보고된 형식상의 구간 길이다. 실제 생성문을 다시 읽은 내용 분석, 통계적 길이 증가 재현, H1 지지, 과잉 추론·정답 포기 판정으로 확대하지 않는다.

네 응답의 **EOS까지 전체 길이는 계속 검열**돼 있다. 닫는 think 태그는 EOS가 아니므로 EOS 미관측과 모순되지 않는다. 기존 문서의 '길이 증가 판정 불가'는 자연 종료 길이와 연구 전제의 재현 판정에 대한 설명으로 유지하고, 이번 태그 위치 관측을 구분해 추가한다.

## 5. 남은 점검 범위와 판정

기존 상세 요약 제출 요청은 충족됐다. 같은 요약 명령·R0·데이터 준비·토크나이저·합성 AWQ 검사를 다시 요청하지 않는다.

우선순위는 [후속 계획](R0_DIAGNOSTIC_FOLLOWUP_20260929_KO.md)의 **고정 BF16 prefix에 대한 전체 모델 logit·좌표 점검**이다. 기존 두 시퀀스(보고상 150·161토큰), B/S/Q/C/Cw 다섯 상태와 B 반복, 전체 forward 12회·새 생성 0회라는 범위는 유지한다. C↔Cw 비교에서 두 LayerNorm을 원래 값으로 되돌렸을 때의 차이에 초점을 둔다. bias 잔차 0 여부도 재구성 과정에서 확인하되 별도 실행 조건을 추가하지 않는다.

고정 원본 `bf947e29f52e3f666e3263efac149dae0ac18d00`의 [auto_scale.py](https://github.com/ruikangliu/Quantized-Reasoning-Models/blob/bf947e29f52e3f666e3263efac149dae0ac18d00/methods/awq/auto_scale.py)와 [auto_clip.py](https://github.com/ruikangliu/Quantized-Reasoning-Models/blob/bf947e29f52e3f666e3263efac149dae0ac18d00/methods/awq/auto_clip.py)를 읽었다. 탐색 함수와 scale/clip 적용 함수가 분리돼 있어 저장된 값을 재적용하는 구현을 준비할 수 있다. 실제 재구성 실행은 하지 않았으며 shape·dtype·순서·고정 quantizer 대조와 당시 모델과의 동일성 한계는 그대로 남는다.

다음 실행기를 준비할 때 요구할 사항:

1. 모델 로딩 전에 29개 입력 파일을 고정 참조의 보고 해시와 대조하고 원래 실행 commit·모델 revision·runtime을 확인. 승인 범위와 입력 일치 여부를 별도로 검사.
2. 저장된 scale/clip을 재적용해 상태를 구성. 새 AWQ 탐색·calibration·새 문제·생성을 호출하지 않음. 재구성이 불가능하면 기록하고 중단.
3. norm의 참조 RMS와 BF16 재적용 후 잔차를 추가 기록. B↔S, B↔Q, Q↔C, C↔Cw 및 B 반복의 공통 위치 logit·분포·EOS log-probability를 분리해 측정.
4. 유한 값·입력/위치·범위·12회 기록을 만족하면 진단 수집 완료로만 표시. 기능적 허용오차는 미정이며 자동 동등성 PASS를 내지 않음.

현재 후속 실행기는 미구현이고 위 새 모델 forward는 미승인·미실행이다. 준비 작업은 진행할 수 있지만 GPU 실행 명령은 아직 제공하지 않는다. 기존 R0 승인을 다시 받을 필요는 없으며, 새 모델 점검은 사용자가 명시한 기존 범위 밖이므로 실행 전에 별도 범위 승인이 필요하다. 512토큰 종료 관측 후보는 이 점검 뒤의 별도 제안으로 유지한다.
