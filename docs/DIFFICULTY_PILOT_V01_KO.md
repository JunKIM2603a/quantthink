# 난도별 자체 문제 탐색 v01 — 세션 02

**후속 갱신(2026-09-30):** 사용자가 토큰 상한 확대 재시험을 요청했다. 현재 다음은 [32K·전체 문맥80응답 재시험](LONG_GENERATION_V01_KO.md)이며 [향후 예산 원칙](GENERATION_BUDGET_POLICY_KO.md)을 따른다. 기존 결과는 보존하고 새16문맥96회 점검은 미승인 보류한다. 아래 내용은 그 이전 설명·준비·실행 기록이다.

최초 구현: **20문제·실행기·채점기를 작성하고 CPU 검사17개 통과. 작성 환경에는 PyTorch/Transformers 및 사용자 GPU가 없어 모델을 실행하지 않았다. 현재 사용자 결과 상태는 다음 문단을 따른다.**

최신 상태: **80/80개 원본 기록과 두 재개 백업**을 대조했다. EOS는 BF16 25/40·AWQ 12/40이며 형식 미판정4개는 모두 단위 설명으로 수동 정답을 확인했다. 자동 난도 판정은 INCONCLUSIVE로 보존하고, 수동 보완표에서 BF16 D1이8/8 EOS·정답 조건을 충족한다. [원본·수동 답안·문맥 마스크 검토](DIFFICULTY_EVIDENCE_REVIEW_20260929_KO.md)를 따른다. 이후 [CPU 마스크 결과](SDPA_MASK_REVIEW_20260929_KO.md)에서 설치 코드의 차단 동작을 확인했다. 다음은 [승인된 고정 prefix 진단](FIXED_PREFIX_DIAGNOSTIC_V01_KO.md)의 실행·결과 검토이며 실제 GPU 결과는 아직 없다. 실행·재개·내보내기를 반복하지 않는다. 최초 검사17개, 재개 검사14개, 내보내기 검사5개는 과거 작성 시점의 검증이며 이번에 반복하지 않았다.

사용자는 “시험문제를 난이도에 따라서 여러개 만들어서, 어느 난이도 쯤에서 시험이 통과하는지 확인해보자”라고 요청하고 다음 명령을 요구했다. 이 요청에 따라 아래 제한된 자체 문제 시험을 준비했다. 이전 R0 승인 기록은 그대로 두고 이번 시험 범위를 별도로 기록한다. 표본 수·시드·예산·통과 경계는 요청을 구현한 사전 기본값이며 사용자가 각각의 숫자를 명시적으로 승인했다고 기록하지 않는다. 실행기는 이 파일과 고정 설정의 범위만 제공한다.

## 문제와 난도

검토용 [한글 문제 20개와 정답·풀이](DIFFICULTY_QUESTIONS_V01_KO.md)를 함께 제공한다. 실행 문제는 [`fixtures/difficulty_ladder_v01.json`](../fixtures/difficulty_ladder_v01.json)에 고정했다. 각 문제의 영문 입력, 한글 번역, 정확한 정수/분수 정답과 한글 풀이를 포함한다. 모델에는 영문 문제와 공통 답안 지시문만 보낸다. 정답·풀이·난도·문제 ID는 보내지 않는다. 두 조건에서 언어·지시문·입력 토큰을 동일하게 유지한다.

**D1~D5는 임시로 붙인 자체 난도다. MATH 공식 Level, MATH-500 재현 또는 모델의 실측 난도가 아니다.** 실제 결과가 순서대로 어려워지지 않아도 표본을 바꾸거나 결과를 숨기지 않는다. 아래 문제들은 이번에 작성했지만 익숙한 수학 유형이므로 학습 자료와의 비중복·비노출을 보증하지 않는다. 문제 유형·입력 길이도 난도와 함께 달라지므로 난도 자체의 인과 효과를 식별하는 설계는 아니다.

| 단계 | 문제 4개의 내용 | 목적 |
|---|---|---|
| D1 | 할인·세금, 거스름돈, 일차방정식, 직사각형 넓이 | 기본 계산과 답안 형식의 기준점 |
| D2 | 순차적으로 남은 물, 합동 작업률, 주사위 조건부 확률, 자리수 역전 | 여러 조건과 기준량 연결 |
| D3 | 하한 있는 정수 해, 합동식, 내접원 반지름, 근의 대칭식 | 수학적 변환 선택 |
| D4 | 원형 비인접 배치, 서로소 개수, 홀수 합 확률, 두 선의 교점 넓이 | 제약 조건·중복 계수·연립 추론 |
| D5 | 다항식 계수, 분수 디오판토스 방정식, 금지점을 피하는 격자 경로, 완전순열 조건부 확률 | 포함배제·생성함수·경로 분해 등 심화 조합 |

정답 20개는 별도의 정확한 산술·정수 열거·다항식 반복 곱셈·격자 동적 계획·순열 열거로 대조했다. 이는 정답표 검증이며 모델이 문제를 풀었다는 근거가 아니다. 수식·집합 등 일반 MATH 답안을 포괄하는 채점기로 확대하지 않는다.

## 통과 기준

1. **응답 성공:** 자연 EOS 종료이며, 생성된 `</think>` 뒤 최종 영역의 단 하나의 `\boxed{}` 답이 정확한 정답과 같다. 중간 숫자/중간 박스는 정답 근거로 쓰지 않는다. `</think>`는 EOS가 아니다.
2. **문제 안정 통과:** seed 42·43의 두 응답이 모두 성공한다.
3. **난도 PASS:** 해당 조건의 8개 응답 모두 EOS로 종료하고 채점 가능한 상태에서, 4문제 중 적어도 3문제가 안정 통과한다.
4. **난도 FAIL:** 8개 모두 관측·채점 가능하지만 안정 통과가 3문제 미만이다.
5. **난도 INCONCLUSIVE:** 한 응답이라도 누락·실행 오류·상한 종료·파싱 모호함이 있다. 검열을 오답으로 치환하지 않는다. 상한 도달 전 정답 박스가 나와도 자연 종료 성공으로 세지 않고 별도 집계한다. 마지막 허용 토큰이 EOS이면 관측된 EOS로 센다.

3/4 기준은 소규모 문제 탐색을 위한 운영 기준이며 유의성·동등성 경계가 아니다. 두 시드는 독립적인 8개 문제로 취급하지 않는다. 작은 표본으로 모집단 정확도나 유일한 난도 경계를 확정하지 않는다.

전체 5단계를 미리 정한 순서대로 수행한다. 쉬운 단계 실패나 두 모델의 차이를 이유로 나머지를 선택적으로 생략하지 않는다. 요약은 단계별 표와 D1부터 연속으로 PASS한 최고 단계를 함께 표시한다. D2가 FAIL인데 D4가 PASS이면 두 결과를 그대로 남기고 비단조성을 표시한다.

**두 모델의 불일치가 나와야 통과하는 시험이 아니다.** BF16 정답/AWQ 오답, BF16 오답/AWQ 정답, 둘 다 정답, 둘 다 오답과 관측 가능한 쌍 수를 구분한다. 둘 다 틀린 상태를 성공적인 동등성으로 해석하지 않는다. 전체 자연 길이 차이는 두 응답이 모두 EOS일 때만 값이 있고, 이는 관측 가능한 쌍에 한정된다. 검열률과 전체 생성 길이 기록을 함께 남기며 EOS 표본만 골라 전체 길이 증가를 주장하지 않는다. 닫는 think 태그 앞 구간 길이는 별도로 표시한다.

기존 [MATH train 28문제·8,192토큰 후보](REALISTIC_INPUT_PILOT_PLAN_20260929_KO.md)는 별도 초안으로 보존한다. 이번 명령은 그 후보, MATH-500, 새 Pile 입력, R1, KL 매칭, H1/H2, 7B를 실행하지 않는다.

## AWQ 재구성과 남은 검증

먼저 기존 `run.json`·28개 계층 파일의 바이트 SHA-256을 제출된 검토 참조와 로컬에서 대조한다. 기준은 `configs/r0_diagnostic_input_review_v01.json`이며 새 첨부나 기존 요약 재실행은 필요 없다. 고정 원본 모듈의 파일 해시도 확인한다. 모두 읽기 전용이다.

모델 로딩 후 **BF16 생성을 시작하기 전에** 28개 recipe의 계층·shape·scale/clip 경로·BF16 정확한 재구성 가능성을 검사한다. 이후 고정 원본의 apply_scale → apply_clip → pseudo_quantize_tensor 순서로 적용하며 search_scale/search_clip과 calibration은 호출하지 않는다. 저장 dtype·shape 가정이 맞지 않으면 중단하고 원인을 보고한다.

현재 AWQ 조건의40개 원본 기록과28개 recipe 재적용·탐색 없음·파라미터 해시 및 실행 commit의 코드/자료 참조를 검토했다. 실제 가중치 배열을 이 환경에서 다시 해시한 것은 아니다. 원래 R0에는 전체 AWQ 파라미터 해시가 없으므로 재구성 모델을 원 실행과 바이트 단위로 같다고 인증할 수 없다. 조건 이름을 `awq_w3_replay`로 구분하며 재구성 실패 시 AWQ 탐색을 다시 돌리는 대체 경로는 없다.

본 시험이 전 난도 PASS여도 **좌표 변환·norm 복원·전체 모델 logit 동등성은 별도 미완료**다. 현재 B/S/Q/C/Cw 실행기 후보·고정 입력·판정 규칙은 [고정 prefix 진단 v01](FIXED_PREFIX_DIAGNOSTIC_V01_KO.md)에 있다. 실용적 기능 동등성 한도는 미정이다. 이번 실행기는 그 전체 진단 실행기가 아니다. `model_ready=false`, H1/H2 미검증 및 세션 02를 유지한다.

## 최초 실행 명령 — 기록 보존용

현재80개 원본 기록 검토가 끝났으므로 아래 최초 실행 명령을 반복하지 않는다. CPU 마스크 확인도 완료됐다. 현재 후보와 계획 조회 명령은 [고정 prefix 진단 v01](FIXED_PREFIX_DIAGNOSTIC_V01_KO.md)을 따른다. 아래는 기존 캐시와 결과 폴더가 있는 사용자 GPU PC의 최초 실행 기록이다.

```bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates
git pull --ff-only
python scripts/run_difficulty_pilot.py --execute \
  --r0-dir results/local/r0_v03 \
  --upstream-dir results/local/awq_reference_v03 \
  --output-dir results/local/difficulty_v01 \
  --device cuda:0
```

최초 실행용 명령이다. 출력 폴더가 이미 있으면 새 실행은 중단하며, 미완료 결과에만 재개 안내의 `--execute --resume`을 사용한다. 기존 run.json은 백업하고 완료 응답을 보존한다. 생성마다 run.json을 갱신하고 정상 완료 또는 실행 중단 시 summary.json을 작성한다. 정상 상태는 DIFFICULTY_PILOT_EXECUTED_PENDING_REVIEW이며 연구 PASS가 아니다. `--execute` 없이 실행하면 모델·토크나이저를 로드하지 않으며, `--resume`만 주면 저장된 완료/미완료 개수를 읽기 전용으로 확인한다.

완료 또는 중단 뒤, 아래 명령은 저장된 생성만 읽는다. 현재 제출된 summary.json은 이미 검토했으므로 같은 요약을 다시 만들 필요는 없다.

```bash
conda activate quantthink
cd ~/quantthink
python scripts/summarize_difficulty_pilot.py \
  --run results/local/difficulty_v01/run.json \
  --output results/local/difficulty_v01/review_summary.json
```

`review_summary.json`이 이미 있으면 `--output` 없이 같은 요약을 화면으로 확인할 수 있다. 원본 run.json·전체 생성 ID는 공개 저장소에 올리지 않는다. 우선 터미널 표와 `review_summary.json`을 전달하면 난도별 정오·EOS·검열·두 시드 안정성 및 두 모델의 차이를 검토할 수 있다. 실제 생성문이 필요한 파싱 모호함은 다음 검토에서 해당 사례만 확인한다. 자동 채점과 별도로 실제 생성문의 최종 영역을 검토하기 전에는 평가 타당도를 완료로 기록하지 않는다.

## 검증 근거

- 작성 환경: Python 3.12.14, 표준 라이브러리. 새 `tests/test_difficulty_pilot.py` 17개 통과.
- 검증: 정답 20개, 최종 영역/분수 파싱, 중간 정답 배제, 검열·마지막 EOS, 두 시드·비단조 난도, 누락/중복/입력 불일치, 별도 실행 범위, recipe 메타데이터·dtype, 원본 SHA-256·읽기 전용 CLI.
- 현재 근거: 사용자80개 원본 ID/요약·실행 코드/상태 해시·재개 보존 일치, 형식 미판정4개 수동 정답. 설치 코드의 CPU 마스크 결과도 검토 완료. 남은 검증: 문맥 경계의 실제 생성 영향, 원 R0 가중치 동등성, 평가기의 일반 타당도, B/S/Q/C/Cw 전체 logit 비교. 작성 환경의 모델/CUDA 실행은 없음.
- 구현 대조: 고정 AWQ commit bf947e29f52e3f666e3263efac149dae0ac18d00의 auto_scale.py·auto_clip.py와 Transformers v4.51.3의 Qwen2 소스. 기존 R0/준비/합성 AWQ 테스트는 재실행하지 않음.
