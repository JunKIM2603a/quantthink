# 세션02 수락 기준·독립 확인 설계안 — 2026-09-30

**현재는 설계 단계다. 이 문서는 새 GPU 실행·생성·자료 다운로드를 승인하거나 시작하지 않는다.** R0, 자체20문제·80응답, CPU 마스크, 고정 prefix12회, 저장 배열 CPU 감사, 종료 prefix6회의 결과 검토를 마쳤다. 기존 실행을 다시 제출하거나 반복할 필요는 없다.

후속 갱신: [새16문맥 좌표 점검 v01](FUNCTIONAL_HOLDOUT_V01_KO.md)에 입력·운영 한도·실행기를 구체화했고 새 CPU 검사8개가 통과했다. 최대96회·새 생성0의 실행은 별도 승인 전이다. 이 패널은 아래 전체 생성/모집단 수락 설계의 일부인 **한 단계 구현 영향 점검**이다. 미래 정확도·종료율·길이의 주 결과, 의미 있는 차이와 검정력은 여전히 미정이다.

## 이번 결과가 바꾼 다음 질문

[종료 prefix 결과](TERMINATION_PREFIX_RESULT_REVIEW_20260930_KO.md)에서 BF16 종료 직전 문맥에는 양쪽 모델의 EOS만 남고, 동일길이 AWQ 문맥에는 양쪽 EOS가 제외됐다. 한 사례의 종료 시점만 더 살피는 작업으로는 AWQ가 다른 경로를 만들게 된 과정이나 길이 차이의 원인을 확인할 수 없다. 현재 질문을 다음 세 가지로 구분한다.

| 확인할 대상 | 현재까지 확인한 것 | 남은 판단 |
|---|---|---|
| 구현과 자료 수집 | 고정 입력/코드/설정·파라미터 해시, 예산, B 반복 일치 보고 | 원시 배열을 직접 받지 않은 검증 깊이를 유지해 기록 |
| 좌표 변환의 기능적 영향 | B↔S·Q↔C·C↔Cw의 비영 분포 차이와 동점 관계 | 후속 연구의 판단을 바꾸지 않을 수락 한도와 독립 확인 |
| AWQ 행동·종료 변화 | 자체 시험의 종료 차이, 고정 문맥의 B↔Q 분포 차이 | 미관측 표본과 실제 생성 경로에서의 재현·원인 구분 |

BF16과 AWQ가 같은 답·길이·분포를 내는 것은 양자화 구현의 통과 조건이 아니다. 구현 검증은 스케일링·좌표 변환·참조 모델 보존이 의도대로 작동하는지를 다룬다. 양자화 때문에 생기는 B↔Q 차이는 연구 대상이다. 이를 혼동해 B↔Q 차이가 없을 때까지 문제를 쉽게 만들거나, 차이가 커질 때까지 시점을 고르지 않는다.

## 사전에 고정할 수락 규칙안

다음 규칙은 향후 프로토콜의 후보이며 H1/H2 동결이나 실모델 준비 완료 선언이 아니다.

1. **자료 수집 실패 조건은 그대로 유지한다.** 입력/참조/파라미터 해시, 예산, shape, 유한성, 필수 기록 누락은 중단·검토 대상이다. BF16 동일 조건 반복이 다르면 원인을 먼저 확인한다. 성공한 수집 자체를 기능적 동등성 PASS로 부르지 않는다.
2. **좌표 비교와 양자화 비교를 분리한다.** B↔S·Q↔C·C↔Cw는 변환 부작용을, B↔Q는 양자화 변화를 측정한다. 같은 logit이어야 한다는 엄밀한 기준은 현재 비영 차이로 충족되지 않았다. 실용적 수락 기준을 채택하려면 별도의 근거가 필요하다.
3. **기능적 한도는 후속 판단에 허용되는 변화로 정의한다.** 정확도·종료율·검열을 포함한 길이 지표 중 주 결과와 최소 의미 있는 차이를 먼저 고른다. 그 결정에 비추어 좌표 변환 영향의 허용 한도를 정하고, 입력/위치별 TV·후보 집합·EOS 차이의 어떤 요약과 불확실성으로 판정할지 고정한다. KL만 하나 맞추거나 현재 RMS/TV를 간신히 포함하는 수치를 사후 선택하지 않는다. 전체 생성과 모집단에 대한 숫자 한도는 **미정**이다. 새16문맥 프로토콜의 평균TV .01·최대TV .05는 제한된 한 단계 운영 한도 제안이며 이 미정 항목을 대신하지 않는다.
4. **판정은 세 갈래로 남긴다.** 독립 확인에서 사전 한도 충족을 뒷받침하면 해당 범위 수락, 한도 초과를 뒷받침하면 의미 있는 변환 영향, 자료·정밀도가 부족하면 판정 불가다. 표본 평균이 작다는 이유만으로 수락하지 않는다. 문제 단위 의존성을 고려하고 연속 토큰129개를 독립 사례129개로 계산하지 않는다.
5. **측정 경로를 고정한다.** 비교 목적에 따라 full-sequence/no-cache와 실제 생성 cache 경로를 구분한다. T=1 전체 어휘와 실제 decoding 조건의 필터 결과를 함께 기록하고 경계 동점·무한대 KL을 보존한다. 현재의 float64 필터 결과를 GPU FP32 샘플링 재현으로 대체 표기하지 않는다.

## 독립 확인 입력과 종료 해석

- 현재 자체20문제, D2-03/D3-01 및 그 생성 경로는 이미 결과를 보고 선택한 탐색 자료다. 다음 확인에서 사용한다면 개발·진단 자료라는 지위를 유지한다. 독립 확인 표본으로 재분류하지 않는다.
- 새 입력은 결과를 보기 전에 목록·선택 규칙·자료 역할을 고정하고 calibration과 겹침을 대조한다. EOS 성공/실패·B/Q 불일치를 본 뒤 입력을 고르는 방식은 탐색으로 명시한다. 자료 출처·문항 수·시드 수·문맥/생성 예산은 아직 미정이며 R1·MATH-500이나 새 Pile 추론을 자동으로 사용하는 계획이 아니다.
- 종료 현상은 같은 문맥에서 모델만 바꾼 차이와, 서로 다른 생성 경로를 비교한 차이를 분리한다. 같은 길이의 문맥도 최종 답 작성 여부와 추론 단계가 다를 수 있다. 닫는 think 태그와 최종 답 완료 여부는 구간 구분 보조 기록이지 정확도·과잉 추론의 단독 판정 기준이 아니다.
- 실제 생성 재현에서는 입력·seed·sampling 설정·EOS/PAD·마스크·cache 조건과 검열 처리를 고정해야 한다. 현재43개 상한 응답의 최종 정오나 자연 종료 길이를 임의로 채우지 않는다.

## 다음에 확정할 산출물과 세션 전환

전체 생성 확인 프로토콜에는 **주 결과, 의미 있는 차이의 한도, 좌표 변환의 수락 기준, 독립 입력 목록/선택 규칙, 시드·예산, 실제 생성 runtime, 채점·검열 처리, 판정 불가 처리**를 한 묶음으로 기록해야 한다. 그 전에 준비한 새16문맥 점검의 범위와 판정은 [해당 프로토콜](FUNCTIONAL_HOLDOUT_V01_KO.md)을 따른다. 한도나 표본을 변경하면 근거와 적용 시점을 남기고 기존 결과를 소급 PASS로 바꾸지 않는다. 구체적 구현·범위·예산이 준비된 새96회에 대해서만 승인을 판단한다. 이미 승인·완료한 R0/12회/6회의 승인을 다시 요청하지 않는다.

현재는 기능적 검증·평가 타당도·후속 재현 기준과 생성 처리량 근거가 미완료라 세션03으로 전환하지 않는다. 다음 단계에서 KL 매칭·대조군 계획을 다룰 수 있도록 설계를 준비하되 실제 R1·MATH-500·장문맥·H1/H2·7B 또는 추가 생성은 시작하지 않는다.
