# 새16문맥의 좌표 변환 점검 v01 — 구현 완료·실행 승인 대기

**후속 갱신(2026-09-30):** 사용자가 토큰 상한 확대 재시험을 요청했다. 현재 다음은 [32K·전체 문맥80응답 재시험](LONG_GENERATION_V01_KO.md)이며 [향후 예산 원칙](GENERATION_BUDGET_POLICY_KO.md)을 따른다. 기존 결과는 보존하고 새16문맥96회 점검은 미승인 보류한다. 아래 내용은 그 이전 설명·준비·실행 기록이다.

현재 세션은 **QuantThink 02 — 환경 구축·BF16/AWQ 재현**이다. 사용자의 2026-09-30 07:15:49 한국시간 “다음 작업도 진행해줘” 요청에 따라 입력·수락 규칙·예산·실행기를 준비했다. 직전 안내의 다음 작업은 프로토콜 작성이었으므로 이 요청을 새96회 GPU 예산의 사전 승인으로 확대 해석하지 않는다. 기존 R0·20문제·12회·6회의 실행이나 승인을 반복하지 않는다.

## 질문과 검증 대상

질문은 **양자화 가중치를 비교하기 위해 적용하는 스케일링·좌표 변환이, 새 문맥에서 다음 토큰의 선택 확률을 정한 한도보다 많이 바꾸는가**다. [종료 prefix6회](TERMINATION_PREFIX_RESULT_REVIEW_20260930_KO.md)는 이미 결과를 보고 고른 한 사례였다. 이번에는 모델 결과를 보지 않고 작성한16개 문맥을 모든 상태에 똑같이 넣는다.

한정된 고정 패널의 구현 영향 점검이다. 통계적 모집단 동등성·최종 정답률·자연 생성 길이·H1/H2를 판정하지 않는다. 통과하더라도 model_ready=true나 세션03 전환은 자동으로 일어나지 않는다.

## 고정 입력

- [fixtures/functional_holdout_v01.json](../fixtures/functional_holdout_v01.json)에 서로 다른 문제16개와 사람이 작성한 풀이 앞부분을 고정했다. 대수·경우의 수·확률·정수론 각4개이며, 각 분야에 설정·계산·검산·최종 답 작성 단계가1개씩 있다.
- 예: 격자 경로가 특정 점을 피하는 경우의 수, 조건부 동전 확률, 모듈러 합동, 일률 합산. 문제와 풀이 전문은 fixture에서 확인한다. 제공된 풀이를 입력으로 쓰므로 모델이 문제를 스스로 풀었다고 평가하지 않는다.
- 기존20문제와 문항 텍스트의 정규화 정확 중복은 없고16개 정답을 별도 정수/분수 계산으로 확인했다. 의미상 유사 문제나 모델 사전학습 오염이 없음을 인증하지 않는다. MATH의 공식 난도나 대표 표본도 아니다.
- 기존 모델 revision·캐시 tokenizer·chat template로 질문을 만들고, 작성된 assistant prefix를 이어 붙인다. 마지막32개 logit 위치를 모두 측정한다. 전체 문맥을 계산하므로 뒤32토큰만 잘라 입력하지 않는다.
- 각 prefix는32토큰 이상, prompt+prefix는768토큰 이하이고 EOS를 포함하면 안 된다. 실제 token 수·ID·위치·해시는 실행 전 기록하며, 한도를 넘으면 자르지 않고 중단한다. 아직 실제 tokenizer로 이16개 입력을 처리하지 않았다.

이는 기존 모델 출력에 대한 진단 선택 밖의 새 입력이다. 기존 결과를 알고 설계했다는 사실은 남으며, 무작위 독립 표본이나 미래 H1 확증 세트로 재분류하지 않는다. 이 실행 후에는 해당 입력도 관측된 진단 자료가 된다.

## 모델 상태와 비교

| 상태 | 구성 |
|---|---|
| B | 고정된 원본 BF16 |
| B_repeat | 같은 B·같은 입력 재평가 |
| S | B에 저장된 AWQ scale만 적용 |
| Q | B에 저장된 scale/clip/W3 g128 recipe 적용 |
| C | Q를 원래 좌표로 역변환한 값을 BF16으로 적용 |
| Cw | C의 선형 weight를 유지하고 원본 norm/bias 복원 |

수락 대상은 **B↔S, Q↔C, C↔Cw**다. B↔B_repeat는 반복 점검이고 B↔Q는 양자화 차이의 관측이다. B↔Q가 같아야 통과하는 규칙을 만들지 않는다. 모든 상태의 전체 파라미터 해시는 앞선12회 보고와 일치해야 한다.

## 수락 규칙의 수치 제안

주 지표는 T=0.6·top-p=.95 float64 필터 후 **TV(total variation)**다. 이 값은 두 분포가 어떤 토큰 집합에 부여하는 확률 차이의 최댓값이다. 예를 들어 TV=.01이면 그 위치에서 “EOS를 뽑는다” 같은 어느 토큰 집합의 확률도1%p보다 크게 차이 나지 않는다.

세 좌표 비교가 각각 다음 조건을 모두 충족해야 한다.

| 기준 | 제안한 한도 | 의미 |
|---|---:|---|
| 문항별32위치 평균 TV를16문항에 동등 가중한 평균 | ≤0.01 | 고정 패널에서 한 단계의 평균 확률 변화 예산1%p |
| 전체16×32개 관측 위치 중 최대 TV | ≤0.05 | 평균에 숨는 국소 변화도5%p 이내 |
| 최종 답 문맥4개의 마지막 위치에서 EOS 후보 포함 여부 불일치 | 0건 | 완성 답 직후 종료 후보가 변하는 사례를 별도 보호 |

**1%/5%는 이번 제한된 구현 점검을 위한 운영 한도 제안이다.** 논문이나 라이브러리가 보장하는 AWQ 공인 기준이 아니다. 평균과 국소 위험을 따로 제한하도록 선택했으며 과거 RMS/TV를 재채점해 통과시키지 않는다. 과거 결과를 이미 본 상태에서 새 입력용 기준을 제안했다는 사실을 숨기지 않는다. 새 결과를 받은 뒤 한도를 넓혀 통과시키는 것도 허용하지 않는다.

이 한 단계 한도는4096토큰 전체 답변의 일치, EOS 발생률 또는 정확도 차이1%를 보증하지 않는다. 현재512개 위치를 독립 사례로 간주한 p-value나 신뢰구간도 만들지 않는다. 미래 생성 결과의 의미 있는 차이·H1 동등성 한도는 별도의 주 결과·검정력 설계로 정한다.

수락 경계를 의미 있는 변화에 맞춰 미리 정해야 한다는 방법론적 원칙은 [Lakens(2017)의 원 논문 정보](https://research.tue.nl/en/publications/equivalence-tests-a-practical-primer-for-t-tests-correlations-and/)를 참고했다. 그 논문은 위1%/5% 수치나 이 고정 패널의 동등성 검정을 제시하지 않는다.

## 계산 상한과 보호 조건

| 항목 | 실행 승인 대상 후보 |
|---|---|
| 입력·상태 | 16개×6상태 |
| forward | **최대96회**. B 반복이 다르면32회에서 중단 |
| 처리입력 | 최대73,728토큰, 실제 길이에 따라 감소 |
| 문맥·위치 | 최대768토큰·입력별마지막32개 위치 |
| 새 생성 | **0토큰**, sampling 없음. 초기화 seed42 |
| 원시 logit | 96개 `[32,151936]` float32, 본체1,866,989,568바이트(약1.87GB/1.74GiB)와 JSON/헤더 |
| runtime | 기존1.5B·BF16·SDPA·cuda:0, window=None·use_cache=false |
| AWQ | 저장 recipe 재적용. calibration 탐색·모델 다운로드 없음 |
| 출력 | `results/local/functional_holdout_v01/run.json` 및 `.npy` |

기존 패키지와 고정 소스·R029개 파일을 검증하고 모델은 한 번에 하나씩 유지한다. 새16개 입력에 필요한 tokenization만 수행하며 기존 tokenizer 점검·데이터 준비·합성 AWQ 검사를 반복하지 않는다. 실행 시간은 미측정이며 forward 수·토큰 수를 실측 시간으로 바꾸어 표현하지 않는다. 출력 폴더가 있거나 오류/중단이 생기면 자동 재개·재시도·예산 확대를 하지 않는다. 원시 배열과 입력 ID는 공개 Git에 올리지 않는다.

## 판정과 결과에 따른 다음 행동

- 수집 실패·누락·비유한 값·해시 불일치: 완료/통과로 처리하지 않고 현재 파일과 오류부터 검토한다.
- B 반복 차이: `FUNCTIONAL_HOLDOUT_BASELINE_REPEAT_DIFFERENCE`. Q 등 후속 상태를 실행하지 않고 runtime 변동을 검토한다.
- 96회·80비교 완료: `FUNCTIONAL_HOLDOUT_COLLECTED_PENDING_REVIEW`. 이 문자열은 자료 수집 상태다.
- 세 좌표 비교가 모두 한도 안: `WITHIN_ONE_STEP_BOUNDS_ON_FIXED_PANEL`. 이번 고정 패널의 한 단계 범위만 수락 후보로 보고, 실제 생성/cache·평가 타당도 및 독립 확인 설계로 이어간다.
- 하나라도 한도 초과: `COORDINATE_EFFECT_EXCEEDS_ONE_STEP_BOUND`. 해당 변환을 영향 없는 전처리로 취급하지 않는다. 변환 방식을 고치거나 별도 대조군으로 유지하는 설계를 검토하며 허용치를 넓히지 않는다.

B↔Q의 차이는 보고하지만 이 수락 판정에는 넣지 않는다. EOS 후보 불일치, 경계 동점, 무한대 KL과 최대 TV 위치를 보존한다. 어떤 결과에서도 종료 지연의 원인이나 H1/H2를 확정하지 않는다.

## 준비 검증과 실행 상태

[실행기](../scripts/run_functional_holdout.py)·[계약/판정](../scripts/functional_holdout_contracts.py)·[설정](../configs/functional_holdout_v01.json)을 준비했고 새 CPU 검사8개가 통과했다. 정답의 별도 계산, 새 입력/위치/예산, 한도 경계와 국소 이상, EOS 후보 불일치, B/Q의 수락 대상 제외, 누락/중복, 승인·해시·잔여 예산, 미승인 실행의 import 전 차단을 확인했다. 기존 시험은 반복하지 않았다.

이 환경에는 PyTorch/Transformers/GPU가 없어 실제16문맥 tokenization·모델 forward·CUDA는 실행하지 않았다. 새 검사 통과를 실모델 실행 통과로 표시하지 않는다.

현재 `functional_holdout.authorization=PENDING`, `remaining_forward_calls=0`이다. 사용자가 처음 제한한 예산 범위와 AGENTS.md8의 실행 기록 규칙에 따라 **새96회 범위**를 승인해야 실행할 수 있다. 기존 R0/12회/6회의 승인을 다시 요청하는 것이 아니다. 승인 전 `--execute`는 모델·토크나이저 import와 결과 폴더 생성 전에 중단한다.

필요할 때만 아래 읽기 전용 계획을 볼 수 있다. 계획 출력 재제출은 필요 없다.

```bash
conda activate quantthink
cd ~/quantthink
git switch setup/session-01-research-gates &&
git pull --ff-only &&
python scripts/run_functional_holdout.py --plan
```
