## 세션 01 완료 근거

2609.23125v1과 2609.06473v1의 관련 본문 대조를 [후속 기록](NOVELTY_FOLLOWUP_20260929.md)에 남겼다. 원문 접근 문제는 해소했고, [사용자 제출 토크나이저 PASS](TOKENIZER_CONTRACT_REVIEW_20260929.md)의 해시·입력 배열을 대조했다. 이제 [R0 검토안](R0_REVIEW_PACKET_20260929_KO.md)에 기존 문헌표와 통합한 제한된 기여 범위와 구체적인 실모델 점검 계획을 정리했다. 이 범위의 채택, R0 프로토콜 수락 및 연구 실행 승인을 현재 사용자 응답으로 기록했다. 토크나이저 재실행은 요청하지 않는다. 기존 보고서의 '노이즈 비교가 최초' 또는 '어느 결과든 논문이 된다'는 문구를 사용하지 않는다. R0 범위만 수락했고 후속 프로토콜·H1/H2는 초안이다. 기존 준비 작업에 더해 승인된 R0 실행이 허용된다.

2026-09-29 후속 준비에서는 [재현 준비 v0.2](REPRODUCTION_PREPARATION_V02_KO.md)를 작성하고, AWQ 가중치 좌표 변환·GSM8K 수치 평가·개발 문제 후보 분리 및 평가 입력 대조에 관한 새 CPU 테스트 32개가 통과했다. 이는 합성 자료 검사이며 당시 실제 모델 어댑터·데이터 출처·수동 판정 검증을 완료했다는 뜻은 아니다. 사용자에게 전달하는 새 안내 문서는 한글로 작성한다.

v0.3에서는 고정 원본 함수를 사용하는 Qwen2 AWQ 어댑터, 데이터 출처·바이트 검증 로더, R0 실행기 후보를 구현했다. 작성 환경에서 새 CPU 검사 29개와 기존 연계 검사 32개가 통과했으며, 실제 Qwen2 CPU 연결 검사 3개는 의존성 부재로 건너뛰었다.

이후 [사용자 제출 합성 AWQ PASS](SYNTHETIC_AWQ_REVIEW_20260929_KO.md)를 검토했다. 단위 테스트 요약은 31개 통과·1개 건너뜀이며, 구현 4개와 정책 해시가 저장소와 일치했다. 512토큰 소형 모델의 두 상대 RMS는 약 0.3702%·0.3665%로 합성 한도 5% 이내다. SDPA 경고 조건도 고정 소스로 확인했다. 원본 보고서 바이트·생성 commit·건너뛴 검사 이름은 확인하지 않았다.

다음 준비 작업으로 고정 데이터 출처·개발 100문제·calibration 65,536토큰 후보 준비를 진행했다. 명령에는 conda activate quantthink을 포함한다. 사용자 데이터 준비는 Pile JSONL 행 길이 상한에서 중단됐다. [수정 기록](DATA_PREPARATION_FIX_20260929_KO.md)에서 동일 원본 SHA-256·최대 행 4,744,757자를 확인하고 오류를 재현했다. calibration 읽기 한도를 수정한 뒤 zstandard 0.23.0으로 전체 179,996행을 해석했다. 새 검사 11개와 기존 연계 검사 29개가 통과했고 의존성이 없는 Qwen2 검사 3개는 건너뛰었다. 당시에는 전체 데이터 후보 생성의 재실행이 남아 있었다.

이후 2026-09-29 05:18:26 UTC의 [사용자 데이터 준비 완료 보고](DATA_PREPARATION_REVIEW_20260929_KO.md)를 검토했다. 코드 4개·설정 3개 해시가 일치했고, 원본 파일 3개를 독립적으로 확인했다. 개발 산출물 3개도 다시 만들어 파일 해시 일치를 확인했다. Calibration 261문서·65,536토큰은 사용자 보고 및 집계 대조 근거이며, 산출물 2개 바이트와 전체 토큰 배열은 이 환경에서 직접 확인하지 않았다. 검토 참조를 고정하고 R0에 연결했으며 관련 새 검사 7개와 기존 연계 검사 29개가 통과했다. 의존성 부재로 Qwen2 검사 3개는 건너뛰었다.

데이터 준비를 반복할 필요는 없다. 제한된 기여 범위, 합성 2문제 × BF16/AWQ·응답당 최대 128토큰의 R0 계획과 실행 승인을 기록했다. 이후 실모델 R0의 실행 완료 보고를 받았으며, 장문맥·H1/H2는 계속 미실행이다.
